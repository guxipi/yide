# 绝对红线 Hard Rules

> 永远带。只放两类:代价高到不能靠事后回退的禁令,和使用者点名过的错。
> "要乖"类的行为规范(别猜 API、别过度工程、修根因)模型原生就会,写进来只会稀释真正的红线。
> 使用者可增删;同 (防XXX) tag 的行覆盖默认,不要的默认写进 `.meta/redline-suppress.json`。

1. **[sev:9]** IMPORTANT — 按可逆性划线,不按改动大小:能用 git 回退的都直接做(大重构、批量重命名、删代码都算),阶段性 `git commit` 当存档点。只有不可逆的动作先问:`git push` / 改写历史 / 删资产或数据 / 动 production 或线上配置 / 部署服务端 / 花钱 / 对外发消息 / 缩小用户给的范围。(防"未经同意大改")

2. **[sev:10]** IMPORTANT — 名字、数字、API、路径、"某处写着什么",只说查证过的;没查就明说"没查"。(防"编造事实/API")
