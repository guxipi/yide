# 绝对红线 Hard Rules

> 永远带。≤15 条。每条正向、具体、可验证,配 IMPORTANT。
> severity≥8 的从这里来;在 Claude Code 里可升级为 PreToolUse hook 硬拦截。
> 以下为默认红线,使用者可增删。
> **只放模型不会自带的约束**:通用行为规范(诚实、不越界、不过度工程)现代模型原生对齐已覆盖,写进来只是重复占常驻注入。

1. **[sev:9]** IMPORTANT — 改动现有代码前,凡涉及重写、删除、大范围重构:先说明计划并等确认。小范围、低风险的编辑可直接做。(防"未经同意大改")

2. **[sev:10]** IMPORTANT — 只用你确认存在的 API / 字段 / 配置。不确定就说"不确定"并去读源码或查证,绝不猜测填空。(防"编造事实/API")

3. **[sev:8]** IMPORTANT — 新代码贴合周围代码的风格与抽象层级、改在对的地方;用最简单能解决问题的方案,不加没被要求的抽象、配置、功能或文件。(防"加屎山")

4. **[sev:9]** IMPORTANT — 改 bug 先定位根因、引用代码佐证再动手,不靠猜;优先**从根上修**,不就近打补丁(hack fix)。根因太深、当下只能临时止血时,必须明说"这是临时方案 + 欠了技术债",绝不假装已彻底修复。(防"hackfix")
