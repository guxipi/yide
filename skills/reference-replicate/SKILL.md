# 对标复刻 SOP(观察 → 测量 → 派单 → 在景验收)

这份 SOP 解决一个具体问题:我们对着参考图做东西,细节总是要用户来指出。2026-10-16 荒漠砖块一天里,砖厚、离地高度、坡度、碎块尺寸四条都是勾哥先说的,复盘出四个根因,每一步都对着其中一个:

1. 只在纯色底上渲单件,厚度、离地高度这类相对地面的量在图里根本不存在,没法比。
2. 终审拿自己写的参数清单当尺子("到没到 30°"),不重新看参考,等于自评。
3. 数字是从模糊裁图目测或拍脑袋给的(碎块 0.3-0.9m,实际 1.2-2.0m),没用尺子量。
4. 每轮只改用户上一句话,没人主动把参考里所有差异列全。

一句话:**先量后说,在景对比,盲列差异,逐层过表。**

## 0 锁参考(开工前一次)

先给物件分类,再给每一类锁 1 张主参考 + 最多 2 张辅参考,写清文件名和裁区坐标(原图像素)。逆向和每一轮验收都只用这组。要换参考先记原因。禁用 loading 插画、概念图、另一类物件的图当尺寸来源。

## 1 观察:先整张,再逐层填表

**先看整张原图**,在里面找出目标物件的**所有实例**(至少 5 个,尽量覆盖完整/破损/边缘/被遮挡几种状态),记下各自坐标。只看一个裁区一定会漏:砖的厚度信息就藏在整张图右下那堆掀起砖的侧面上,网格区里根本看不出来。

然后按下面七层逐行填**观察表**(模板在 `observation_template.md`)。每一行都要写:数值或事实 / 从哪个实例、哪个坐标量的 / 置信度。看不清就写"待核"和原因(像素不够、被遮挡),**不许猜一个数填上**。顺序不能换,前面的层决定观感,最容易漏:

| 层 | 要回答的问题 |
|---|---|
| L1 体积与离地 | 多厚?高出地面多少?侧面露不露、露多少?投影多长多软?埋地还是浮在上面?谁盖住谁?**由多种材质叠成的东西(台地、崖、岸)先写层序**:从下到上每层是什么、哪层包住哪层的边、哪层伸出去(10-16 丛林崖壁把"草掩膜"当成台地顶,做成一整块绿盖子,勾哥:"绿色的这个盖子不应该存在,应该要么是沙地包住一点岩壁边缘,在上面再有一层草皮") |
| L2 轮廓 | 直边还是曲边?角是直角、切角还是圆角,多大?不规则的幅度?尺寸分布(量 N 个实例给范围,不给单值) |
| L3 排布 | 网格还是随机?间距、错位、旋转抖动?密度怎么渐变?边缘怎么收(一刀切/渐稀/破碎带)?叠压比例? |
| L4 中间层细节 | 倒角、缝、裂纹、磨损各是什么:几何形成还是画的?宽度多少? |
| L5 光照响应 | 受光面/背光面/倒角亮边的明度比;明暗交界软硬;反光颜色 |
| L6 颜色 | 各区域中位色 hex;实例**之间**的色差范围 vs 实例**内部**的色差 |
| L7 动态 | (适用时)动画、VFX、随相机的变化 |

### 各类目标在七层里额外要问的(七层通用,下面是各类最容易漏的)

| 类别 | 额外必查 |
|---|---|
| 地面/铺装(砖、砂、路) | 单元尺寸与透视节距;缝的成因与宽度;边缘过渡带宽;谁覆盖谁;块间 vs 块内色差 |
| 地被植被(草皮、草甸、草芽) | 厚度与侧裙;轮廓两级起伏(大起伏+小叶瓣)与占周长比例;叶片高/宽/倒向;密度中心与边缘渐变;根尖色渐变;遮不遮角色脚;影子是否被植被吃掉 |
| 地形(崖、台地、坡) | 高差占屏比例;顶沿亮带宽;立面色带 hex 序列;嵌石凸出厚度与分布;崖脚收法;阴影区占屏 |
| 物件/建筑 | 剪影与主体块数;中间层细节(捆带、横杆、叠板外凸量);倒角宽度比(硬物 ≤3%、石质 6-10%);和地面的接触(埋、压、影);成组摆法 |
| 角色/怪 | 头身比、剪影辨识件;占屏高;与地面色的互补关系;脚下圈和投影 |
| VFX | 大小相对角色倍数;实心色块/白芯/外缘的层次与 hex;持续帧数与节奏(L7 必填,要用视频逐帧);压在地面上的可读性 |
| 光影/整屏构图 | 主光方向;影子色 hex、暗度比、软边宽;暗区占屏比例;高光上限;后处理(bloom、tonemap)痕迹 |
| UI | 安全区与占屏;字号相对屏高;描边/底板;层级对比度 |

## 2 测量:用尺子,不用眼睛估

所有尺寸一律用 `refkit.py` 在原图像素上量,用"身高单位 H"表示,需要米时再换算到本项目角色身高。

```bash
py refkit.py crop    REF.png --box x0,y0,x1,y1 --zoom 4 --out c.png   # 放大看,最近邻不糊边
py refkit.py measure REF.png --p1 x,y --p2 x,y                       # 量像素
py refkit.py color   REF.png --box x0,y0,x1,y1 --k 3                 # 中位色+暗/中/亮三簇
py refkit.py sheet   REF.png --boxes "..;..;.." --out inst.png       # N 个实例拼一张对比
```

**描轮廓到地面米(trace)**:参考里目标的掩膜(现成 mask png,或 `--color #RRGGBB --tol N` 颜色阈值)按同深度单元节距反算成贴地点列。比例参数就是下面透视量法里量出的三个数:同深度单元 x 节距 `--pitch-px`、单元米数 `--cell-m`、y/x 比 `--yx`(或局部俯角 `--pitch-deg`,取 yx=sin)。
```bash
py refkit.py trace MASK.png --pitch-px 65 --cell-m 1.58 --yx 0.92 [--box x0,y0,x1,y1]    [--sigma 1] [--step 0.04] --out outline.txt --preview prev.png [--compare 旧.txt]
```
输出 `x z cut`(米,x 右 z 屏幕上方,逆时针,居中),`cut=1` 是被 `--box` 或图边截断的点(不是真实边,别当边缘加叶瓣)。`--box` 只截一段;`--step` 点距;`--sigma` 只去掩膜台阶,默认 1px。默认填洞(花丛不算边)。预览左=叠图,右=米制平面图(1m 网格)。回归:1-20 左草皮 mask 按 65px=1.58m、yx 0.92、box 580,0,2400,1080、step 0.04 跑,和 Lab_TurfOutline_E.txt 面积比 1.000、点到线平均距 0.007m、cut 点数一致(139)。

**一轮同时标定三个数**时,别拿一个俯角换算,按本节后面的"同深度比"量。没有标定参数时输出单位是像素,仅用于看形状。

斜俯视下有透视压缩,量法有讲究(10-16 已证实旧口径"砖宽 0.58 身高"就是没处理压缩算出来的):

- 游戏相机一般是**强透视**:mo.co 1-20 同一块方砖,屏幕 x 宽从画面顶到底变化 ±20%,局部俯角从 43° 变到 70°。所以别拿一个俯角做 sin/cos 换算(10-16 总控这样算出"砖宽 0.41H",是错的)。
- **在同一屏幕深度比**:先在角色脚下那一行量重复单元(砖、地块)的 x 节距,物件尺寸先换成"几个单元",再乘"单元 x 宽 ÷ 角色投影高"。屏幕 x 方向在同一深度不压缩,最可靠。
- 立着的高度(墙、侧壁、厚度)同样只和同深度的单元节距比(例:南侧暗墙像素 ÷ 同深度砖节距 = 0.14-0.16),交付验收也用这个屏幕比值,不先换算成米。
- **屏幕比值只在局部俯角相同时可直接比。** 参考里那块地方的局部俯角(由同深度方砖 y/x 节距比 ≈ sin 俯角 得到)和我们相机在同位置的俯角不同时,立着的高度要按 cos 比例换算:我方应显示的侧壁 = 参考侧壁比值 × cos(我方俯角)/cos(参考局部俯角)。10-16 碎块按参考 64° 处的侧壁直接换算厚度,我们 V5 是 46°,结果做厚了约 1.5 倍。
- **H 换米分三个方向,不能都乘角色身高**:立着的量 h = r×身高;屏幕横向(同深度 x)w = r×身高×cos(我方俯角);屏幕纵向的地面进深 d = r×身高×cot(我方俯角)。V5 46°、H=3.1m 时三个系数分别是 3.1 / 2.15 / 3.0 m。10-16 丛林地面 spec 用了"H≈2.9m",崖壁 spec 横向直接乘 3.1,两份 Fable 审稿各自独立推出同一个修正。
- **计数一律按面积(每 H²),不写"每屏 N 个"**:参考是横屏帧,一帧地面约 200H²;我方竖屏一屏只有 30H² 上下,照"每屏 4-10 簇"摆会密 3-15 倍(10-16 丛林地面三叶草)。
- **cos 换算只用于"立高 ÷ 地面单元"**。立着的东西(柱、墙、树干)直接和同深度的角色投影高比,角色也是立着的,两者吃的是同一个俯角压缩,比出来的 H 就是真高,不再乘或除 cos。10-16 丛林 POI spec 拿屏幕值当真高,还准备再除 cos,Fable 关口按"柱侧面 ÷ 角色"重算后发现门柱高了 1.5-2 倍。另外,量立高时要扣掉顶面椭圆(帽顶、墙顶),那是顶面,不是立面。
- 透视强弱本身要验证:同一单元在画面上中下三处的 y/x 比如果不同,就是透视;用"单元是正方形"和脚下光圈互相校验。
- 小于 5px 的特征(缝宽、斜面宽)单帧量不准,换更近或更清楚的帧再量,或者标"待核",不许拿模糊放大图定数。

## 3 派单:每个数都能追到观察表的某一行

派单只写数字和来源,不写形容词。每一条都要标"出自观察表 Lx 第几行 / 参考坐标"。没有来源的要求不进派单。派单必须写明:

- 交付物 = **在景对照图**:物件放在地面上(按 L1 的埋深)、本项目相机俯角、本项目主光方向、旁边立角色身高标尺、带周围环境(地面/邻接物);和参考裁区按 H 同比例并排。纯色底单件图只能当附图,不能当验收依据。
- 执行方要用同一张观察表,逐层自填"我方值 / 参考值 / 差多少",和 sbs 并排图一起交。
- 每轮新版也要和**当前最好版**并排,不如上一版就回退。

### 形状和排布:描,不要生成

**由很多小单元拼成的有机体(树冠、花丛、灌木),先做单元库再拼整体。** 先交 6-10 个单元(叶片)的单页图:大小、深浅、轮廓各不相同,叶形从参考剪影描,和参考里对应那片叶同比例并排;单元过了再按参考的排法(树冠是从顶部一圈圈往下放,顶小底大)拼整冠,整体外形也不是完美球体。10-16 丛林树冠 r1、r2 直接写整冠生成器,叶片是参数菱形,两轮都被勾哥判"几乎和 reference 没有关系",他指的路是"先做单片叶子……先打磨大概 8 片叶子"。荒漠草芽一次过,正是因为叶基叶尖直接从参考掩膜读点。

10-16 勾哥指出:AI 摆的第一轮,砖也好草皮也好,整体形状和边缘总是规整、有规律、不自然。根因有三:

1. 观察表把形状记成"范围"(叶瓣 0.22-0.38 砖),执行方写代码在范围里均匀随机取。均匀随机的每个特征都来自同一个分布,大小差不多、间隔差不多,看上去就是"有规律的乱"。参考是美术手画的:有一两个大凹口、一段很长的平静边、一段密集的小叶瓣,大小和间隔是成团的、有层级的。
2. 形状是孤立生成的。参考的轮廓是跟着环境走的:草皮贴着台地边、沿着砖边、在墙角拐弯;我们的是空地上凭空长出一个饼。
3. 生成算法本身带对称:极坐标 r(θ)+噪声只能出凸饼,三角扇从中心放射,网格加抖动还是网格。

所以第一轮就要这么做:

- **轮廓直接描参考。** 观察时把参考里目标的掩膜抠出来(颜色阈值,存 mask png),用透视反算到地面,按身高单位缩放,作为我们第一版的真实轮廓;要变化就旋转、镜像、切开重拼几块参考轮廓,不要从参数生成。砖区同理:把参考里的网格线、缺砖、合并大板、碎块位置描成一张图照着摆。
- 描图只管大轮廓:参考是视频帧,掩膜会把小于约 10px 的叶瓣/锯齿抹平(10-16 草皮 r2 描图后细尺度只有参考的 55-65%)。大轮廓用描图,沿边的小特征按观察表实测的大小/间距分布重新加上,再用 shape 的细尺度项验收。
- 实在要生成(铺大面积),从描下来的参考轮廓里统计真实分布(每个凸起的大小、间隔),按这个分布抽样,不用均匀范围;强制层级:先放 1-2 个大凹口和一段平静边,再在剩下的边上成团放小叶瓣。
- 轮廓由环境决定:先定它贴着谁(墙、台地边、砖边、崖),那一段跟着邻接物走。
- 三角化用约束三角剖分,不用中心扇;网格类排布在描图基础上再破。
- **叶瓣库 `lobes`**:大轮廓用 trace,沿边小特征用库。`refkit.py lobes MASK --pitch-px .. --cell-m .. --yx .. --out lib.json` 沿参考轮廓在"谷点"之间切段,每段存弦长 w、凸出 h、最高点位置、32 点归一化剖面(轮廓顺序保留,碰截断边的段丢掉,花苗/折叠等退化段丢掉),同时出 `*_montage.png`(上行按真实相对大小,下行归一化同宽,绿=叶瓣灰=平静段)和 `*_overlay.png`(谷点标在原图轮廓上)。必须先看拼图:是叶子形才入库;谷点标错就调 `--min-prom`(谷点显著度,占√面积比例,默认 0.004)、`--base-frac`、`--min-w`。
  重放:`refkit.py lobes place --lib lib.json --outline 大轮廓.txt --seed N --out new.txt --preview p.png`。按库里**连续片段**(保留成团和平静段的顺序)沿大轮廓基线放,整片段随机镜像、整体大小做 lognormal 抖动(`--jitter`),不逐叶瓣均匀随机;`--size-mult` 整体放缩;输入轮廓会被平滑成基线(`--base-sigma-w`,单位叶瓣宽),所以输入应是没有小叶瓣的大轮廓。命令末尾打印库来源/输入/重放结果三行 shape 指标(地面栅格化),重放结果应贴近库来源。已建库:1-20 左草皮,放在 `samples/moco120_turf/`。放完自动检测自交:相交的叶瓣压平成基线并报告压平数,残留自交说明输入大轮廓本身有问题。
  **用法边界**:勾哥 10-16 判定零加工描图效果最好。`lobes place` 只在描图丢了参考里确实存在的小叶瓣时才用(掩膜抹平 <10px 的叶瓣),并且要在交付说明里标明补的是参考哪一段、对应的参考坐标;不是用来给没有小叶瓣的边凭空加边缘。
- **交付前用数字卡住**:`refkit.py shape` 分别量参考掩膜和我方截图掩膜(实度=面积/凸包、细尺度起伏、凸起个数与大小/间距变异系数),再用 `flicker` 把两个轮廓叠闪。实度差 >0.05、凸起大小 CV 低于参考 0.8 倍、细尺度起伏低于参考一半,就不交。1-20 草皮参考值:实度 0.81-0.83,凸起大小 CV 0.42-0.46,间距 CV 0.57-0.64,细尺度起伏 0.46-0.58%√A。注意掩膜被画面边缘截断时间距 CV 不准。
  **一条命令做完拦截**:`py refkit.py regress --ref 参考掩膜 --best 当前最好版掩膜 --new 新版掩膜 [--new-color #RRGGBB --new-box x0,y0,x1,y1]`(best/ref 同样有 `-color/-box`)。打印三者指标表;新版相对最好版出现任一项:实度离参考更远(>0.01)、凸起大小 CV 更低(>5%)、细尺度更低(>5%),打印"退步"并**退出码 1**,执行方不交。另外实度差>0.05、大小CV<参考 0.8 倍、细尺度<参考一半只打印"门槛未过"警告,加 `--gate` 则退出码 2。没给 `--best` 只做绝对门槛提示。三张掩膜必须是同一目标、同一口径(同相机同裁区)抠出来的。`--new-outline 新版.txt` 可同时检查新版轮廓自交,有自交算退步(退出码 1)。

## 4 验收:盲列差异,再看自报

1. **先盲看**:不读执行方自报和自己写的参数,只看在景并排图(加 `refkit.py flicker` 闪烁对比),按 L1→L7 把我方这张图也填一遍观察表。
2. 逐行和参考那张比,差异按层排序:L1/L2 的差异优先,颜色最后。
3. 然后才读执行方自报。它列了你没列的,说明你漏看了,补进表;你列了它没列的,写进下一轮派单。
4. 结论只有两种:过(找不出三处以上差异,且不比当前最好版差)/不过(附按层排序的差异表)。"比上一版好""符合参数"都不算过。
5. **一轮只发一张全量清单。** 每次验收把 L1-L7 全部差异连同量好的数一次列完、一次发出,执行方一轮全改完再交。不许看一处发一条:执行方正在跑长回合时,后发的消息排队,它会按条一轮一轮做,每轮都要截图、提交、回报。10-16 砖地缝色、缝宽、裂纹、碎块下沉、接触暗分成五条消息,变成四轮。真有急事追加,先停它的回合,再发合并后的完整清单。
6. **独立第二观察者**:主体物件、整屏、地面这类重要验收,开一个独立 subagent(不给它看你的结论和派单),只给参考图和我方图让它填同一张观察表,再把两份合并。两份都漏的才是真的看不出;一份有一份没有的,回头再看原图。

小摆件(柱/箱/碎石/小装饰)在实机尺度读对即收,只跑 1-2 层,不进第 5 步。

## 5 收尾:观察表入库

每一类物件的观察表和量过的数(带坐标)存进项目的共享笔记/参考库,下次同类物件直接复用,不重量。用户这轮指出的点,如果观察表里没有对应行,说明这张表的问题清单有缺,把那个问题加进模板,别只改这一次的物件。

**第二观察者不是可选项。** 10-16 试跑:总控自己填表只抓到 4 项,独立 subagent 按本 SOP 带工具填了 20 多行,补出强透视、静态砖无外投影、这一帧根本没有斜躺砖、直缝不错缝、叠压很少等,其中三条推翻了总控已经派出去的口径。主体件、地面、整屏的第一份派单之前就要跑一次,不要等验收才跑。subagent prompt 要点:只给参考图路径、本 SKILL 和模板、refkit 用法、角色大致坐标;不给我们的结论;要求 ≥8 个实例、每行带坐标和置信度、看不清写待核;最后附"复刻团队最容易做错的 5 件事"。

## 常见翻车(都真实发生过)

- **描完又加工**:10-16 草皮 A 块描图后又接长、镜像、加流苏、补叶瓣、改崖侧,每一步都离参考更远;勾哥最认可的是左上 B 块——纯描图、只旋转平移、零加工。规则:描图结果先原样交一版;后续任何加工都要指出参考里对应的那一段,否则不做。

- **往参考里加它没有的东西**:"掀起斜躺的砖""行错缝"是凭印象写进铺砖法的,1-20 这一帧里都没有。参考里看不到的特征,不写进派单;想加,先找到有它的帧。

- 把裁图放大到发糊再"量",得出斜面偏高 → 砖减薄,方向做反。
- 给数前没量,碎块尺寸差 2 倍。
- 只看俯视轮廓和颜色,厚度、侧壁、投影整层漏掉。
- 把 L2 的软肩部当成轮廓也要圆,做成鹅卵石;参考是直断口 + 软肩。
- 用另一类物件的参考图定尺寸(拿神庙纪念墙定前哨墙砖块大小)。
- 照小图标做立体符号(徽章、标牌),描出来上下反了、带着像素台阶,总控只挑了台阶没看出反(10-16 Boss 箱骷髅,勾哥"骷髅反了")。符号件验收第一眼先和原图标同向并排,核"认得出是什么、朝向对",再看工艺;符号用矢量形重画,不描低分辨率图标。
- 改了全局参数去追一张图(OBJ_TINT),其它物件全跟着变。
