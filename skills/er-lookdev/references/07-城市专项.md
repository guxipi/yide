# 07 城市专项:玻璃反射、窗内假室内、发光招牌配 bloom、路面贴花

来源标记:〔读〕〔测〕〔推〕同 01。主要来源:Unity 6000.3 手册(反射探针、贴花、bloom 各页)和 URP 源码(`Bloom.shader`、`DecalRendererFeature.cs` 等)、van Dongen 2008 年的 interior mapping 论文全文和他 2018 年的博客、Playground Games 讲 Forza Horizon 4 窗户的文章、Willmott 讲 SimCity 的讲稿(只读了文字层)、Riot VALORANT shader 文章、Arm 的本地 cubemap 文章、bgolus 的 matcap gist、Shader Graph 17.3 官方示例文档。

这一块公开资料最弱。风格化游戏讲自己玻璃做法的一手资料只有 VALORANT 一篇;讲霓虹招牌做法的一篇都没读到;俯视镜头用假室内的资料没有。下面凡是标〔推〕的配方都没有出处,用之前在引擎里并排验。画面口径(玻璃不用平行斜亮条、要宽大低频的面状反射、相邻窗格连贯)在 vault `013 美术/AI记忆/` 的玻璃那条,这里只讲实现手段。

## 一、玻璃反射

URP 6000.3 现成有什么:

- 没有屏幕空间反射,没有平面反射(官方功能对比表两项都是 No);SSR 还在预览,官方帖说目标是 Unity 6.7。现成的只有反射探针。〔读〕
- 反射探针三种:Baked、Custom(可以直接指定一张自己的 cubemap,和场景里有什么无关)、Realtime(六个面各渲一次,贵)。「手做 cubemap」在 Unity 里就是 Custom 探针或者自己的 shader 直接采一张图。〔读〕
- Forward 路径按物体包围盒在 CPU 上选探针,每个物体最多两个;不在任何探针盒子里就用天空盒反射。相邻两块窗如果是两个物体又落进不同探针,反射会有接缝。〔前半读;接缝推〕
- Box Projection 把 cubemap 当成有限距离的盒子,探针上勾了还要在 URP Asset 里开;URP 的探针盒子只能轴对齐。〔读〕

各种做法:

| 做法 | 原理 | 代价和问题 |
|---|---|---|
| 无限远 cubemap | 反射向量直接查 | 最便宜;和本地几何没关系,同一角度永远同一个反射。全场景共用一张图时物体之间没有接缝 〔读 Arm、Lagarde〕 |
| 本地 cubemap 加盒子修正 | 反射向量和包围盒求交,用交点减拍摄位置去查 | 多几条指令;Arm 就是把它当手机的便宜反射推的;图是静态的,可以预先模糊 〔读〕 |
| matcap | 视空间法线当 UV | 约 10 条指令;平面整面一个颜色,因为法线和视线在平面上都是常数 〔读 bgolus〕 |
| 透视修正的 matcap | 视线改用「相机到该点」的方向 | 约 17 条;平面上 UV 会变。在一整面玻璃幕墙上是什么观感,没有资料讲,要自己试 〔指令数读;观感没读到〕 |
| 反射向量查经纬度全景图 | 一张 2D 图 | 官方示例有现成子图;左右接缝处要自己给导数,否则出硬线 〔读〕 |
| 平面反射、SSR | — | URP 没有,手机上的做法和代价没读到 |

读到的游戏做法:

- VALORANT:高光基本只靠全景 HDR 图(实拍或预先从关卡里拍的),粗糙度放在预先模糊好的 mip 里;只有接近镜面的东西(瞄准镜的玻璃)才用真实场景反射。美术直接在静态 HDR 图上手绘亮斑来控制高光的形状,因为漫反射主要来自一盏方向光,就在那个方向画亮斑。〔读〕
- Forza Horizon 4:每格玻璃的法线略有差异,让各格反射角不同。这是写实方向,和我们要的「相邻窗格连贯」相反:要连贯就不加逐格法线扰动。〔前半读;后半推〕
- Dagor 引擎的假室内 shader:玻璃反射用手做 cubemap 或加载地图时生成的环境 cubemap;手做的外景图只适合低楼层,高层用了里面的东西会显得过大。〔读〕

由读到的原理拼出的做法(没有任何原文这样写,待验证):同一立面的玻璃在自己的 shader 里用世界空间反射向量查同一张低频的环境图(cubemap 或全景图),不走场景探针。平玻璃上的变化来自各像素视线方向不同,相邻窗格法线相同、共用一张图所以连续,朝向不同的立面查到图上不同区域所以有差异。反射的形状由这张图决定,美术可以像 VALORANT 那样直接在图上画宽大的亮块。〔推〕

## 二、窗内假室内(interior mapping)

- 算法(van Dongen 2008):在片元里做射线求交。把空间看成每隔固定距离有一层天花板和一面墙,相机到像素的射线分别和最近的那层天花板(或地板)、两个方向的墙求交,取最近的交点,用交点坐标去读对应的贴图。全部在物体空间算,建筑本身不加几何。外墙贴图的 alpha 标出哪里是窗,再和反射混合。〔读论文〕
- 代价(论文数字,2008 年的显卡):基础版加一张固有色和一张反射在 64 条指令以内;代价和屏幕上这种材质覆盖的像素数成正比,和房间数无关;室内贴图分辨率几乎不影响帧率。手机上的指令数或帧时间没有任何资料给。〔读;后一句没读到〕
- 后来的版本:cubemap 版(一次盒子求交加一次 cubemap 采样;Unity Shader Graph 的 Feature Examples 里有现成的 Interior Cube Mapping 示例,带随机旋转);SimCity 把每个房间预投影到一张 2D 图上并拼成图集,房间深度可变;Forza Horizon 4 分三层(窗框玻璃、窗帘、室内),室内是烘成专用格式的平面贴图,一张图集最多 8 个房间,另配一张夜间灯光图。〔读〕
- 斜角度下的问题(Forza 文章):视线和玻璃夹角很小时穿帮会变明显,处理是在这些角度加强菲涅尔、多显示反射少显示室内;房间中央的细节随角度增大而扭曲,处理是把看点放到墙和墙角、压暗地板;远处淡成一张平面图。〔读〕
- 俯视镜头值不值:相机从高处看竖直的窗,正好是上一条说的小夹角,射线大多先打到房间的地板,玩家看到的室内内容少,而且按 Forza 的经验这个角度本来就该让反射盖过室内。底层橱窗同样斜着被看到,读到的资料里只有「浅橱窗」(把房间深度调小)是针对这种情况的。没有任何资料讨论俯视或斜 45 度游戏用它的效果。结论:先把玻璃反射做对,假室内只在底层橱窗做一处小样并排判,不默认铺开。〔推〕

## 三、发光招牌配 bloom

URP bloom 的预滤波(6000.3 源码):

```
threshold     = GammaToLinearSpace(Threshold)      // 面板上的值是 gamma 空间的
thresholdKnee = threshold * 0.5                    // 膝部写死是阈值的一半
color      = min(ClampMax, color)
brightness = max(color.r, color.g, color.b)
softness   = clamp(brightness - threshold + thresholdKnee, 0, 2 * thresholdKnee)
softness   = softness * softness / (4 * thresholdKnee + 1e-4)
color     *= max(brightness - threshold, softness) / max(brightness, 1e-4)
```

- 亮度取的是三个通道的最大值,纯红、纯蓝的招牌只要那一个通道过阈值就出光晕;贡献量是超出阈值的那部分,颜色按原色等比缩小,所以光晕带招牌本色;膝部从半个阈值就开始有一点贡献。默认阈值 0.9 换到线性约 0.79。〔源码读;三条推论和 0.79 是自己算的〕
- 参数:Intensity 默认 0(等于关);Scatter 默认 0.7;Clamp 是参与 bloom 的最大亮度。手机上滤波选 Dual 或 Kawase,Downscale 设 Quarter,Max Iterations 调小,关 High Quality Filtering。〔读〕
- 颜色要亮过 1 需要 URP Asset 开 HDR。HDR 拾色器的 Intensity 每加 1 亮度翻倍。emission 该给阈值的多少倍,没有任何资料给数字。〔读;后一句没读到〕

有光晕但字不吹白:没有读到任何一手资料,下面全是推断,做之前拿一块招牌并排试。

- 字吹白有两个来源:招牌本体的 HDR 颜色超过 1 之后各通道一起顶到上限;bloom 叠回来又加一层。
- 招牌的字面和图案保持在 1 以内保色,只让灯管、边框这些窄的部分给高 emission(用一张 emission 遮罩分开)。
- 光晕不够时,在招牌后面或周围放一张加色混合的柔光面片补。面片是普通透明绘制,形状和颜色都可控,不依赖后处理,代价是透明填充。
- 用 Clamp 限住个别特别亮的像素,免得出过大的光晕。

招牌对周围的照明:

- Forward 每个物体最多 8 盏附加光,手机每个相机 32 盏,时代广场这种几十上百块招牌不可能每块配一盏实时光。〔上限读;结论推〕
- 烘焙自发光:材质的 Global Illumination 选 Baked,自发光面像面光源一样进光照图;只照亮静态物体,角色要靠探针。选 None 就只是自己亮。〔读〕
- 加色面片、贴地的柔光片、不投影的点光:没读到一手资料,是常见做法。〔推〕
- 贴花假光:Decal Shader Graph 有 Affect Emission 开关,但同一版本的功能对比表写 URP「没有自发光贴花」,两处官方文档矛盾,以实测为准。〔读〕

## 四、路面贴花

URP Decal Renderer Feature(6000.3):

- 两种技术。DBuffer:不支持 OpenGL ES,要 DepthNormal 预通道,文档和源码都说它不适合手机的分块渲染。Screen Space:只要深度图,法线从深度重建,只支持法线混合;文档推荐手机用它。Automatic 在手机上落到 Screen Space。〔读文档和源码〕
- 开了 Use Rendering Layers(让某些物体不接收贴花),URP 会把 DepthNormal 预通道带回来。俯视游戏想让路面贴花不投到角色和车上,在手机上要付这个代价。〔读;后一句推〕
- 贴花不走 SRP Batcher(用了 MaterialPropertyBlock);同材质开 GPU Instancing 才合并,多张贴花图拼成图集、用 Projector 的 UV 缩放偏移选格子。投影贴花只作用于不透明表面。〔读〕
- 贴花之间的先后用材质上的 Priority(−50 到 50,小的先画)。投影贴花每像素的成本和手机上能放多少个,文档和电子书都没给数字。〔读;后一句没读到〕

替代做法:贴地的网格贴花。一个 Quad 或贴着路面的面片,alpha 混合或 alpha test,用深度偏移(ShaderLab 的 `Offset`)防和地面打架。它是普通网格,跟着街区模型一起走,不需要深度图和 Decal Renderer Feature。〔定义读 Unity、Polycount;后一句推〕

各类路面元素用哪种,没有一手资料直接回答,以下是按上面的限制推的:

| 元素 | 建议 | 理由 |
|---|---|---|
| 车道线、斑马线、箭头 | 贴地网格贴花(一个材质一张图集),或直接画进路面贴图 | 量大、规则、位置固定、在平地上;投影贴花每个都要读深度 |
| 井盖 | 建进路面模型,或硬边网格贴花 | 硬边、固定位置 |
| 污渍、油渍、裂缝 | 平地上用 alpha 混合的网格贴花;要跨路沿、台阶的才用投影贴花 | 软边、随机摆 |
| 水渍、湿地 | 在路面自己的 shader 里用遮罩或顶点色压暗并提高光滑度 | Screen Space 贴花能不能改光滑度文档没明说 |

alpha test 和 alpha 混合在手机上谁贵见 09 第四节。
