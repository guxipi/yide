# 03 环境光遮蔽(AO)的烘焙和叠法

来源标记:〔读〕〔测〕〔推〕同 01。主要来源:Activision 的 Jimenez 等论文和 SIGGRAPH 2016 幻灯、Unity Graphics 仓库源码(`CommonLighting.hlsl`、URP `AmbientOcclusion.hlsl`)、Blender 手册、Adobe Substance 烘焙器文档、Dota 2 Workshop「Color Texture Light Baking」官方页全文(第二轮读到)、Substance 3D Painter 的 Baked Lighting Stylized 滤镜文档。实测是用 `scripts/ao_lab.py`、`ao_lab2.py`、`ao_lab3.py` 在 Blender 5.1.2 上跑的,Unity 侧用 `scripts/unity_lookdev_lab.cs`(6000.3.5f2 / URP 17.3)。附图在 vault `01 - 星际拓荒重构/07 - AI上下文/翼德地编学习_附图/`。

## 一、遮蔽乘在哪些光上

- 定义见 01。遮蔽 × 固有色,等于「白色天穹、一次反弹、漫反射表面」这个情形下的光照,所以它天生是环境光的可见性。〔读〕
- 物理正确的做法只乘间接光。URP 自己就是这样:材质的遮蔽图只进 `indirectAmbientOcclusion`,乘烘焙光和环境反射,不碰主光;只有屏幕空间遮蔽能通过 Direct Lighting Strength 部分作用到主光上;烘焙遮蔽和屏幕空间遮蔽用 `min()` 合并。〔读源码〕
- 所以在「主光强、环境光弱」的风格化 shader 里,只乘环境光的遮蔽几乎看不见。开和关没区别时先查这个,不要去加大强度或把图拉亮。
- 风格化行业做法是把遮蔽当成画出来的形体明暗,作用在整个漫反射上。Dota 2 把光烘进颜色贴图的理由是游戏内光照很含蓄,法线贴图里的雕刻细节会丢。官方页的分层(数字逐个对过原文):
  1. 底色:角色的主导色。
  2. 遮蔽烘焙:Multiply,80%。
  3. 点光图组:场景里放几盏白色点光渲一张图,这一遍不要遮蔽、关掉投影,材质最好能出高光;通常灯放在不同位置各烘一张再混。上面盖一层 RGB 90 的 Screen 层(85%)把暗部夹住,免得压暗底图。整组以 Soft Light 100% 叠上。原文说它比遮蔽图能抓到更多雕刻信息,两样要分别控制;也是引入「从上到下、由亮到暗」渐变的起点。
  4. 颜色组:Overlay,80%。再复制两份夹住高光和暗部:Lighten 30%、Darken 50%。
  5. 图形图案:Normal,80%。最后整体改善明度渐变、调饱和度。
  原文没有规定灯的方向、数量和距离(「自上而下」说的是渐变,不是灯位),也没有给渐变的幅度。〔读〕
- Substance 3D Painter 的 Baked Lighting Stylized 滤镜是同一类做法的现成工具:输入遮蔽、曲率、法线、世界空间法线四张烘焙图,用一个可调的太阳、三色天空(天、地平线、地面)和两盏附加灯把光照烘进颜色通道,遮蔽对漫反射和高光的影响分开调,另有凹处和边缘两组控制。文档每个参数只有一句话,没有默认值,也没有按高度的渐变项。〔读〕
- 第一轮的推断「参考里跨整个车顶的缓过渡是三层叠出来的」对着参考量过之后要改:参考货车的车顶是平的,渐变在竖直的侧壁上,第三层是「按高度的渐变」而且只作用在下半截。量法和配方见第三节「第三层」。〔测〕

## 二、带色遮蔽

多次反弹近似(Jimenez 2016,Unity 源码原文):

```
real3 GTAOMultiBounce(real visibility, real3 albedo)
{
    real3 a =  2.0404 * albedo - 0.3324;
    real3 b = -4.7951 * albedo + 0.6417;
    real3 c =  2.7552 * albedo + 0.6903;
    real x = visibility;
    return max(x, ((x * a + b) * x + c) * x);
}
```

它是在固有色 0.1 到 0.9、三次反弹、假设周围和本点同色的条件下拟合的:亮而饱和的固有色,遮蔽处会被抬亮并带上自己的色相。〔读〕

**实测到的副作用**:固有色越亮,它把遮蔽抬得越多。黄色(线性 0.80, 0.60, 0.10)上,最暗一成像素的平均值从灰乘的 0.26 抬到 0.49;再叠一层往淡紫插值后到 0.68,遮蔽几乎看不出来。白色上更明显:遮蔽值 0.33 会被抬成约 0.70。所以白车、白墙上想要看得见的软阴影,不能直接套这个公式;要么不用它、只做染色,要么先把遮蔽图压深再喂给它。〔测;白色那个数是按公式手算〕

染色的几种写法:〔推〕

- 往一个有色相的颜色插值:`occl = lerp(_AOTint, 1, ao)`,最暗处是固有色 × tint,不会是灰或黑。
- 渐变图:`occl = ramp(ao)`,中间调可以带色相偏移。
- 强度用 `lerp(1, ao, k)`,形状用 `pow(ao, γ)`。**不要把图的最小值最大值拉满(归一化)**:那会截断并让曲线变陡,过渡带就没了。实测:归一化后最暗一成像素从 0.042 掉到 0.001,暗部直接死黑。白点钉在 1.0,只动 gamma 和强度。〔测〕

其它叠法:

- 进分带项:`t = 分带(N·L * shadowAtten * ao)`,让遮蔽把像素推向带色的阴影色,而不是乘黑,整个画面只有一套阴影色。分带要够软,否则遮蔽的渐变会被切成台阶。〔推〕
- 微阴影(神秘海域 4,Unity 源码里有):`saturate(NdotL + 2*ao*ao - 1)` 乘在主光上,只在光线掠射时起作用,是让烘焙遮蔽影响主光的有物理依据的写法。〔读〕
- 风格化全局写法:`diffuse = albedo * (direct * lerp(1, ao, kDirect) + ambient * ao)`,和 URP 的 Direct Lighting Strength 是同一个设计。〔推〕

## 三、在 Blender 里烘

### 参数实际管什么

- 烘焙类型 Ambient Occlusion 忽略场景里所有灯。〔读手册〕
- 距离:Blender 5.1 里用 `scene.world.light_settings.distance` 设,实测有效。距离就是过渡带的宽度:2 m 宽的货车上,0.2 m 只在缝边出一条线,1.4 m 和 3.0 m 才有跨面的缓过渡;但距离大到接近物体尺寸时,几乎每个点都能看到别的零件,整体会变成一片低对比的灰。〔测;后半句读 Marmoset 社区测试〕
- Cycles 的遮蔽在距离处是硬截断,没有衰减选项(Substance 有 None / Linear / Smooth 三种衰减)。要柔和的衰减,用两三个距离的结果平均,或烘完再模糊。〔读;做法推〕
- 采样:噪点按 1/√N 下降。实测 8 采样的颗粒是 64 采样的 2.5 倍。正式件 256 以上。〔测〕
- **降噪开关对烘焙无效**:实测 `scene.cycles.use_denoising` 开和关,烘出来的图逐项数字完全一样。烘焙的噪点只能靠加采样,或烘完自己做一次小半径模糊(遮蔽是低频信号,1 到 2 像素的模糊不伤它)。〔测〕
- 烘到 32 位浮点图再转 8 位,否则大面积缓渐变会出色带。〔读社区〕
- 边距(margin):用来避免 UV 接缝处因为贴图过滤和 mip 出现的断线。512 的图给 8 像素,1k 到 2k 给 16。〔读手册;数值推〕
- 地面:烘的时候在轮子着地高度放一块大平面,车身下半和底盘才会压暗。实测加地面后整图均值从 0.77 降到 0.60。会开来开去的车,地面遮蔽给弱一点,真正的贴地影交给运行时的 blob 影。〔测;后半句推〕
- 烘到顶点色:Output Target 选 Active Color Attribute。〔读手册〕

### 两层叠加(前两层;竖直面还要加下一小节的第三层)

1. 贴缝遮蔽:距离取物件最大尺寸的 5% 到 10%(货车约 0.10 到 0.25 m)。
2. 形体遮蔽:距离取 50% 到 100%(1 到 2 m),带地面,烘完模糊。
3. 合并:`ao = 贴缝 * lerp(1, 形体, 0.5)`。

实测(标定货车):贴缝层单独均值 0.93、最暗一成 0.50;形体层均值 0.63、最暗一成 0.04;合并后均值 0.75、最暗一成 0.33,缝边清楚、大面有缓过渡、没有死黑。0.5 这个混合比是起步值。〔测;配方本身推〕

### 第三层:竖直面上从上到下的渐变(实测,`ao_lab3.py`)

先看参考(车辆语言基准那张 mo.co 货车,在原图上取色):

- 车顶是平的:屏幕明度 0.88 到 0.96,起伏不到 8%,而且是靠镜头一侧略亮;行李架周围只有贴着件的一圈窄暗边,没有铺开的缓过渡。
- 白厢体的侧壁从上到下明显变暗:屏幕明度 0.77 → 0.54(下 / 上 = 0.71),上面四成多基本是平的,往下才降;同时饱和度从 0.10 升到 0.24,色相一直在 240 到 250 度。换成线性,下 / 上的三通道比是 0.42、0.45、0.66,三个数不相等,是往一个偏蓝紫的阴影色过渡,不是乘灰。
- 这是一帧截图,里面还有这一帧的实时光,分不出多少是烘的、多少是光;下面的配方只是把这张图的明暗分布对上,不代表 mo.co 就是这么做的。

在标定货车上试了五种来源,量侧壁从上到下的剖面(上 = 1)和顶面的平整度:

| 来源 | 侧壁最下 / 最上 | 问题 |
|---|---|---|
| Cycles Diffuse 烘焙,关 Color,白色天穹(题目里设想的做法) | 0.91(线性) | 渐变太弱;而且侧壁整体只有顶面的 0.6 到 0.8,把朝向的明暗也烘进去了,和引擎里的实时主光重复 |
| 一盏点光放在正上方,不投影不带遮蔽(按 Dota 配方的设置,灯位是我取的) | 侧壁是 0 | 灯在盒子正上方时竖直面背对它。Dota 原文是多个位置的几盏灯,面向的是鼓起来的有机形体;车和楼这类盒子只放头顶一盏不行,侧面也放灯又会把朝向烘进去 |
| 带地面的遮蔽,距离 1.5 m(就是第二层) | 0.70 | 上半截平、下半截降,形状和参考像,但幅度不够;把它加重(gamma 3)能到 0.82,代价是顶面也跟着变脏(顶面 5 分位 / 95 分位从 0.95 掉到 0.79) |
| 带地面的遮蔽,距离 3.0 m | 0.65 | 近似直线下降,顶面同样被压 |
| 按世界高度的线性渐变(不烘,shader 里一行) | 自己定 | 和朝向无关,顶面不受影响 |

把它们和前两层叠起来,颜色用 `固有色 × lerp(阴影色, 1, t)`(阴影色取参考的 0.42、0.45、0.66),和参考侧壁的 10 点屏幕明度剖面比均方根误差:

| 合成 | 误差 | 顶面平整度(参考 0.93) |
|---|---|---|
| 两层(贴缝 × 形体混一半) | 0.146 | 0.95 |
| 两层 × 线性高度渐变(最低压到 0.45) | 0.076 | 0.95 |
| 贴缝 × 带地面遮蔽的 3 次方 | 0.114 | 0.79 |
| 两层 × 只作用在下六成的高度渐变 | 0.046 | 0.95 |

结论:

- 两层配方在竖直面上几乎没有渐变(下 / 上 = 0.96),对不上参考;加一层「只作用在下六成的高度渐变」最接近:`g = lerp(0.12, 1, pow(saturate(h / 0.6), 1.5))`,h 是这个面从底到顶的归一化高度,`t = 贴缝 × lerp(1, 形体, 0.5) × g`。0.6、1.5、0.12 是对这一张参考拟合的起步值。〔测〕
- 第三层要和朝向无关(只看高度)。带朝向的烘法(天穹漫反射、点光)会和引擎的实时主光重复算一遍明暗;Dota 敢这么烘是因为它的游戏内光照很弱。〔测加推〕
- 它不需要烘:在顶点 shader 里用物体空间高度算,或者写进顶点色的一个通道(过渡带上下两端要有顶点,见下面「存贴图还是顶点色」)。物理上它对应地面反弹照不到、天光被周围东西挡掉的下半截,Unity 的环境光自己给不出这个(04 第六节:三色环境光的地面色不随高度变)。〔推〕
- 同样的三层换成灰乘,下半截发灰、没有色相(并排板最后一格)。往带色相的阴影色插值这一条不能省。〔测〕
- 没验证的:这是在自发光预览里对的明暗分布,没进 Unity 在实时光下和参考并排;标定货车是盒子,圆的件没试。

### 零件互相穿插的模型烘出来发脏

可能的原因:〔推〕

1. 埋在别的零件里面的面,它的像素只看得到遮挡物,烘成纯黑,再通过边距和贴图过滤渗到看得见的地方。
2. 靠近相交线的点,射线打到隔壁零件壳的背面。
3. 每个零件的遮蔽在相交线两侧不连续。
4. 距离太大,每个零件都在给别的零件投遮蔽。

实测没能在简单件上复现:标定货车的穿插版和布尔合壳版,暗像素占比 0.37 对 0.39,几乎一样。说明穿插本身不一定是元凶,遇到发脏先按下面的顺序排查,不要一上来就认定是穿插。〔测〕

排查和修法,按顺序:

1. 看烘出来的图本身(不是贴到模型上的效果):大片纯黑块在哪,对应模型上哪些面。
2. 查法线朝向是否一致、壳是否闭合。Cycles 没有「忽略背面」的开关。
3. 把距离先降到贴缝那一档重烘,看脏是不是来自大距离。
4. 做一个密封的并集代理(布尔并集或体素重建再倒角),用 Selected to Active 从代理烘到真实零件上。
5. 或者在展 UV 和烘焙之前删掉埋在里面的面。
6. 细节遮蔽用 AO 节点的 Only Local(只算物体自己),再单独烘一遍整件的大范围遮蔽,两者相乘。
7. 会动的零件(车门、轮子)烘的时候不带邻居,免得打开后露出一块黑。

### 存贴图还是顶点色

- 贴图:遮蔽是低频信号,4 m 的车 256 到 512 的单通道就够,只要贴缝遮蔽至少 3 到 4 个像素宽。UV0 有镜像或重叠时要第二套不重叠的 UV。
- 顶点色:不占贴图内存、没有接缝。限制是它只在顶点之间线性插值,过渡带两端都得有顶点,所以大平面的车顶要加支撑环线或网格才存得住「行李架周围的软阴影」(边间距不大于过渡带宽度的一半);三角化的对角线会显形;硬边处顶点是拆开的,会不连续。〔推〕

### 常见毛病对照

| 毛病 | 原因 | 修法 |
|---|---|---|
| 整件发暗发脏 | 距离太大;零件穿插;法线翻了 | 按上一节排查 |
| 颗粒 | 采样不够 | 256 以上;烘后模糊(降噪开关无效) |
| 接合处黑块 | 像素在别的网格里面 | 删埋面;代理烘;Only Local |
| 接缝暗线、晕边 | 边距太小 | 加大边距 |
| 过渡带发硬 | 距离处硬截断;后面又被拉了色阶 | 多个距离平均;模糊;只动 gamma 不动白点 |
| 平面永远到不了白 | 距离无限或太大 | 给有限距离 |
| 进引擎看不见 | 只乘在了环境光上 | 见第四节 |
| 色带 | 8 位图存大面积渐变 | 浮点烘,转换时加抖动 |
| 顶点色出网格或对角线花纹 | 拓扑太稀 | 加环线或改用贴图 |

## 四、Unity 这边

- 存储:贴图的一个通道(线性,关 sRGB;遮蔽用 ASTC 6×6 或 8×8 够);顶点色;光照图(只对静态物体,车这类会动的用不了)。
- 和屏幕空间遮蔽并存:照 URP 的规则用 `min(ssao, 烘焙遮蔽)`,不相乘。分工:烘焙遮蔽管物件自己内部的遮挡,屏幕空间遮蔽(小半径)或 blob 影管物件和世界的接触。〔读文档;分工推〕
- 实测两种接法的差别(URP Lit,遮蔽图 0.5,SSAO 强度 1.6、半径 0.4,镜头离墙脚 35 m):SSAO 不勾 After Opaque、由 shader 接时,背光墙脚没烘焙的地面环境光乘 0.62,有烘焙遮蔽的那条不再变暗(取了 min,仍是 0.5);勾了 After Opaque,两处都再乘 0.62,烘焙那条变成 0.31。受光的墙脚:After Opaque 把整个像素(含主光)乘 0.61;shader 内 Direct Lighting Strength 0.25 时乘 0.83,设 0 时乘 0.90 并且偏暖(只去掉了蓝色的环境光)。〔测〕
- SSAO 的 Falloff 是按相机距离衰减的,不是遮蔽的范围:源码是 `(1 − 深度 / Falloff)²` 乘在遮蔽量上,深度超过 Falloff 就没有遮蔽。我们的镜头离地面 33 到 52 m,Falloff 60 时在 35 m 处只剩 17%、41 m 处 10%、52 m 处 2%。实测同一组参数 Falloff 60 时墙脚乘 0.84,Falloff 300 时乘 0.62。强度 1、半径 0.15 那一组在这个镜头下墙脚 4 cm 处量不出任何变化(Falloff 60 和 300 都一样)。SSAO「开了没区别」先查 Falloff 和半径相对镜头距离够不够。〔读源码加测〕
- URP Lit 的遮蔽图 0.5 在受光地面上只让屏幕值从 #A4A3AE 变到 #9D9999(线性亮度降约 13%,主要是蓝色环境光少了一半),在影子里是线性减半。这就是第一节说的「只乘环境光的遮蔽在受光面上几乎看不见」。〔测〕
- SSAO 各参数的代价(官方评级):Downsample 和 Blur Quality「很高」,Radius 和 Samples「高」(采样从 4 加到 8,GPU 负担翻倍),Direct Lighting Strength 和 Intensity「可忽略」。手机档:Depth 源、开 Downsample、开 After Opaque、Low 模糊、4 采样。〔读〕
- 俯视的风格化游戏里,烘焙遮蔽加 blob 影、完全不开 SSAO 是最便宜的组合。烘焙遮蔽只占一张本来就在采的贴图的一个通道,用顶点色则是零。〔推〕
