## 1. 设计口径(勾哥 10-27 历次改稿,合并后的现行版)

UI 外壳的规则(底色、字阶、按钮、品阶边、底纹、渐变、半透明、投影)全部以 `CARGO_tokens.md` 为准,尤其第十五、十六、十七节;本节只写商业屏和营销视觉特有的口径,不重复 tokens。

**营销层和 UI 外壳分开管。** 礼包包装、卡包、充值卡卡面、KV 是营销画面,目标是"一眼看出买到什么、值多少",可以有放射底、光、人物出框,不受旧 UI 规制限制(10-27:"这是营销视觉,不是 KV,不要被旧 UI 规制限制")。但任何地方都不用高饱和紫→品红→青炫彩叠细线格("太难看了,删掉永远不要这么做")。

**包装上印出礼包的完整内容**(档位名、保底、当期主打件),主角是礼包里最值钱的那件实物,不是"贴纸加一把枪":彩色本体 + 白边 + 品阶色外描 + 深色错位影子,垫放射底,略斜;不做纯剪影,手机上会糊(v4 试过)。写法见 02 章 gun badge。

**物件和包装用 codex 出,画风对 er-icon-gen 的 v4 样张。** 只喂 v4 母版一张,抄 icon 风格句,禁材质词(holographic、glossy、chrome、specular、foil)。喂 KV 场景图会漂成光滑 3D(10-27:"卡画风有偏移啊")。人物 KV 是另一套参考,两套不混。

**商业屏都配礼包 key art,能放人物就放人物。** 人物可以出框(头肩越过卡片上沿),人物、道具、背景同一个光。KV 上不叠纹样。

**能用图说的不用字,每一行都有一个图。** 让玩家选东西就直接摆出物件图,不做文字按钮;任务行左侧是代表具体行动的插画(现成件在 W4 `a/t/t_*.png`)。一次性 / 限定这类卖点用品红贴纸,不写成副标题小字。

**item 是贴纸,品阶看包边。** 品阶只走模切描边,粗细和游戏实装一样(Outline 4px@1080,不加墨线);item 不一定要格子,只有要表达状态或要对齐时才放格子;已领的勾是饱和薄荷,不跟着 item 一起变灰(10-27:"品阶依然通过之前的描边来做""item 不一定要 frame""这个对号颜色怎么这么灰")。

**丰富度按 tokens 第十七节的判定顺序加。** 贴纸 flat 为底,纯色默认;付费内容用低透明紫色炫彩,未到半透明,网点只放装饰带;列头行和内容明显分开。

**人物插画(卡面、KV)要一眼读出卖什么。** 画面里有一件直接讲出商品用途的道具或动作,人物和它有互动;人物拿着宝石摆 pose 不算。动作合人设和目标玩家的语感(ER 偏 Gen Z:不屑、轻松,不是用力、夸张);四肢和服装必须对得上手册。价值写清楚(两段式价值句),角标要从卡面里跳出来,卡边不要黄色描边。做法和坑见 02 章。

**人物按手册定稿。** 参考图只认 `013 美术/角色手册/img/` 的定稿板和表情表;Vesper 认 10-22 之后的当前造型;Tuba 是鳄鱼。不写自编外貌描述。

**被否过、不要再做的**:插画只摆 pose;用力夸张的傻动作;手臂从身后伸出或露出手册里没有的皮肤;角标和卡面同色;剪影当主物件;品阶色渐变格底;厚度底唇、高光弧、立体勾章;折角丝带;按钮一律加底纹;高饱和炫彩细线格;多色浅彩整列铺底;KV 上或要读的内容下面叠纹样;一张表里混五六种底;字标立细规范。

## 2. 可复用部件

gun badge、GUARANTEE 角标、价值贴纸、两段式价值句、人物出框 KV、挂板、任务行、人物插画的画面规则,写法和 CSS 在 `references/02-版式配方.md`。这些是跨屏复用的件,某一屏用哪些、怎么排按本次需求定。

## 3. "像游戏"检查单(每张稿交付前自查,来自 Pinterest 板学习)

1. 这屏有没有"人"在场:店主、当期英雄、礼包代言人。商店屏没有人物 = 不过。
2. 容器是不是物件:卡包、吊牌、票根、充值卡、货箱、夹板,有挂孔、撕口、胶带、钉子这类实物细节;全是平面矩形 = 不过。
3. 一屏至少一处动势:人物或主物件出框、主卡倾斜 -4~-8°、斜切色带。全部水平垂直 = 不过。
4. 每条信息先问能不能用图说:任务行、选项、奖励都配行动图或物件图;按钮上只剩动词和价格。
5. 价值说清楚:保底一行(GUARANTEE)、价值贴纸(x8 VALUE / 1500%)、"立刻得 + 每天得"两段式。买前就知道值多少。
6. 主次有尺寸差:主推卡/付费列/终点格比同类大一档,换底色;同质格连续超过 6 个就拆。
7. 底纹、渐变、半透明、投影按 tokens 第十七节的判定顺序选:纯色默认;网点只在装饰带;KV 上和要读的内容下面不叠纹;付费格低透明紫色炫彩;未到半透明;投影分档。品阶看包边;勾是饱和薄荷;列头行和内容分得开。整屏纯平涂 = 不过;出现第 1 节"被否过"清单里的任何一样 = 也不过。

## 4. 出图管线

完整命令、prompt 模板、验收门在 `references/03-出图管线.md`,脚本在 `scripts/`。三条硬规矩:

- **两套参考不混。** 人物 KV/卡面插画:2 张定稿 KV 当画法基准 + 该角色手册定稿板 + 表情表,写 TIME AND LIGHT。物件/包装:只喂 v4 icon 母版,抄 icon 风格句,禁材质词,纯绿 #00FF00 底。
- **codex 必须关 host skill 并点名参考图。** `codex exec --skip-git-repo-check --enable skip_host_skill_discovery -m gpt-6.1-sol`;prompt 第一句"不读 skill、call image_gen with referenced_image_paths set to EXACTLY [绝对路径]";跑完 `scripts/check_rollout.py` 查 rollout 里 image_gen 真带了几张参考,对不上判失败重跑。
- **出人物图前先实看 mo.co。** 打开 `013 美术/UI_CARGO/ui_qa_2026-10-26/competitor/shop_moco_1.jpg`(商店卡)和 `013 美术/mo.co截图/` 里一张,写两三行提取(人物与底同光、暗部冷紫、无描边、人物占卡高 70~85%),记在本次工作目录的 NOTES 里再出图。

## 5. 交付格式

- 评审稿交 **HTML**(勾哥 10-27 定),不交截图拼图;图片素材相对路径放同目录 `a/`,用 SendUserFile `display: render` 发完整绝对路径。无头截图只给自己自查。
- 一屏一张手机框(1080×2340 画布按 0.5 缩放显示),每屏标题下写一行"这一屏按哪几条口径改的";每轮改稿在页头列"本轮改了什么 / 勾哥上轮意见逐条对应"。
- 版本另存(`board_<x>_v5.html`),旧版不覆盖;生成图进 `a/`,prompt 脚本和 log 留在会话 scratchpad,交付说明里写脚本路径。
- 出图花了几次 codex 调用、哪几张两轮没过,汇报里写清。同一件两轮不中就停,换 approach(改构图或换参考),不再盲调第三轮。

## 6. 不做的事

- 不改 Unity 工程、不接线(那是 ui-placement 的活:CARGO 屏一律改 builder 重跑)。
- 不在 tokens 第十七节以外的地方加纹样和渐变。
- 不自造数值。卡面上的 gems、天数、价格从 Config Hub / BP 表 / 礼包表读;没读到就写占位并在页头标"待真源"。
