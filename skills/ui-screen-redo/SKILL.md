# UI 屏改版前置流程(ui-screen-redo)

勾哥 2026-11-20:「我们非常大的返工在于在做的时候就没有正确的 mind set」。所以玩家视角、信息结构、画风三件事分给三个互相看不到对方结论的角色先各出一份 report,不由作者自己打勾;主控合成稿，再让同一批玩家盲测新稿，过了才给勾哥。

适用：任何新做或改版的 ER 界面、弹窗、HUD 屏(CARGO kit 的屏、礼包和促销弹窗也算;礼包的营销画面出图按 `er-shop-mkt`)。不适用：已批稿落 Unity 时的像素对齐(走 `ui-visual-rework` 的 parity 流程)、只改一个数或一个字的小修。勾哥点名「不用走流程、直接改」的照他说的;他只说「这屏简单、自己审视重做、不用叫 7–8 个 agent」时，免掉的只是多 agent 评审,HTML 稿(现状实拍和新版并排、逐项改了什么、要他定的事)照样先给他批(11-26)。

开工先读 vault `01 - 星际拓荒重构/013 美术/AI记忆/现行口径_UI视觉kit.md` 全文，它是 kit、颜色、字、形、贴纸、面和暗纹、图标画风、交付格式的现行规矩;本 skill 只管流程，不重复那份的内容。

## 这几路各自防的是哪类返工

| 被打回过的一类问题 | 本该在哪一步拦下 |
|---|---|
| 字太多;内部代号当入口名,玩家看不懂 | 1a 文案逐句挑战 |
| 按钮没说清做什么、花什么 | 1a 能不能完成转化 |
| 多个入口被并成一个汇总入口,玩家找不到要的那个 | 1a 转化断在哪 |
| 整屏做成一长条往下滚 | 1b 信息结构 |
| 大事(赛季结算这类)没有大事的分量 | 0 写清分量,1b 按分量排 |
| 主角给错了对象(给了建筑,玩家要的是兵) | 1b 核心信息是什么 |
| 同一屏的件画风不一、连否几版 | 1c 画风审计 |
| 整张图乘色冒充新东西 | 1c |
| 名牌压图标、字太小、平板藏信息 | 2 合成时按画出来的像素排(现行口径已有的门) |

## 第 0 步：页面卡(主控)

模板 `references/page-card.md`,存到这屏的工作目录 `013 美术/UI_CARGO/mock/<屏>_redo/page_card.md`。页面卡是后面三路的共同输入，写不出转化目标就不往下走。

要点：这屏要玩家完成的那一个转化(可判定的一句话，比如「玩家点 PRINT ×10 并付钻」)和最多两个次要动作;入口、频率、这件事在游戏里的分量;配置和代码里查到的真数据;最新实机截图，每个状态一张(工程 `Screenshots/` 按日期 `find -newermt` 找;没有就开编辑器拍，规矩见现行口径「流程」一节和 `references/tooling.md`;只有旧图就停下说;拍图这种只读取证活别去别的会话正在用的编辑器里抢 Play 锁);现有元素全清单(每个按钮、页签、入口、角标、信息块一行);这屏已有的拍板(grep 各系统 `AI记忆/` 和总索引对应分区)。

## 第 1 步：三路独立评审(并行)

三路同时派，各自只拿自己该拿的输入，互相不看对方的 report,主控也不把自己的倾向写进派单。派单模板在 references,照抄再填空;派单里带勾哥这次的原话。

**1a 玩家盲测**:`references/persona-cards.md` 里五个 persona(搜打撤老玩家 0 氪、新手、小 R、中 R、大 R),一个 persona 一个 agent(`general-purpose`,可以用比主控便宜的模型)。只给截图序列和一个任务，不给设计文档、页面卡的转化目标那一行之外的任何内容，不给拍板记录。产出：三秒判断、逐步操作和卡点、每句文案的判定、有没有完成转化、在哪一步放弃。

**1b 信息结构**:UI/UX lead(`ui-ux` agent),模板 `references/ia-lead-brief.md`。给页面卡、设计文档、现有元素全清单、kit 现行稿。要它先找竞品同类屏的实机画面(不要商店宣传图),再按核心信息重排：一屏一件事、入口分级、分组、首屏放什么、低频藏哪、文案改成玩家话，并给出现有元素全清单每一项的去处。产出是结构图(线框可以是简单 HTML 或文字树)加理由。

**1c 画风审计**:主美(`art-director` agent),模板 `references/art-audit-brief.md`。给现状截图、visual 清单、画风基准(tab 图标、六张英雄头像、券 v2 样本、kit v12 样张)。逐个 visual 判留 / 改 / 重出，并回答「它在游戏世界里是什么」:这屏能不能用场景、物件、角色、KV 来讲，而不是面板加字。

三路回来后主控先看一遍：结论是否基于真截图、有没有编造不存在的功能、persona 是否偷看了设计意图。不合格的打回重跑，不自己补。

## 第 2 步：合成可点击 HTML(主控)

主控自己合成，不外派(勾哥的原话和三份 report 都在主控手里)。新结构需要的场景原画、KV、图标、头像、名牌，在出 HTML 之前按 1c 的清单出好(功能图标对标 tab 图标，出 2–3 个方向给对照;出图工具见现行口径「图标」一节和 `er-icon-gen` / `er-shop-mkt` / `codex-executor`)。交勾哥的稿里不放占位图，不放拉伸糊图;实在出不了的在评审页「待拍板」里单列，说明缺什么、为什么。

合成时逐条对账，写进评审页的「对账」页签：
- 1a 的每个卡点：怎么解决的，或者为什么不改。
- 1b 的结构：照做，或者偏离在哪、为什么。
- 现有元素全清单：每一项落在新稿哪里;拿掉的单列，等勾哥批(默认不删)。
- 1c 的每个重出项：新图在哪。

HTML 本身：竖屏手机框(1080×2340 比例)、只用 kit v12 的件(没有的先补进 kit)、按画出来的像素零重叠、字号下限、平板紧凑档不藏决策信息;动效要有按压反馈、出入场、页签切换、领奖或揭晓这类有含义的动效，场景底图和立绘静止。每个状态都能点到(空、满、不够钱、领过、锁住)。

## 第 3 步：第二轮盲测(同一批 persona)

把新稿每个状态截图(无头 Chrome 逐状态截，做法见 `references/tooling.md`;内置浏览器对会话没打开过的本地文件会报打不开，不拿它当判据)，连同同一个任务发给第一轮同样的五个 persona。可以继续第一轮的 agent(SendMessage),让它对比前后。过线标准：五个人都能完成转化;没有新出现的「停住超过一步」的卡点;文案判定里没有「看不懂」。没过就回第 2 步，不交给勾哥。第二轮冒出的新卡点如果只是文案和小件(按钮上没写字、标签看不懂、演示数据挑错),改完可以不跑第三轮,在评审页写明「改后没有再跑」;动了结构就再跑一轮。

## 第 4 步：交评审页给勾哥

骨架和检查项在 `references/review-page.md`。一份评审 HTML,页签依次是：现状和盲测发现 / 新结构 / visual 清单(留哪些、重出哪些，带图)/ 可点击新稿 / 对账 / 待拍板。待拍板项逐项带图写清选项，不弹一句话的选择题。图内嵌、发 SendUserFile 文件卡片。可点击新稿如果超过内嵌体积上限，单独一个文件一起发。

## 批了之后

批过的 HTML 就是这一屏的验收标准，接 `ui-placement`(接线、摆放)和 `ui-visual-rework`(落地和 parity)。现行口径「流程」一节的四项比对、零重叠、两列对照图照旧。

## 写回

勾哥批稿时的每一条纠正，同一回合做三件事：按系统写 feedback 记忆并并进对应现行口径;如果这类问题本该在 1a / 1b / 1c 拦下，把它补进对应 persona 卡或派单模板的检查项;是表里没有的一类问题就在上面「防的是哪类返工」表里加一行(写成一类问题,不写某屏的故事)。这样下一屏开工时三路就已经知道。

## 工具和坑

拍现状图、导出实机数据、codex 出图标切图、可点击稿体积、无头截新稿每个状态,都写在 `references/tooling.md`,脚本在 `scripts/`。开工前读一遍。

完整样例:vault `013 美术/UI_CARGO/mock/starmap_redo/`(页面卡、三路报告、两轮盲测要点、可点击稿、评审页)。

## 成本

一屏大约 7–8 个 agent:五个 persona(两轮，第二轮续用同一个 agent)、UI/UX lead、主美，外加出图。成批改次级页时简化成两个 agent(一个玩家 agent 依次用五张 persona 卡、一个 `ui-ux` 结构 agent,画风审计总控自己做),范围和过线标准见现行口径_UI视觉kit「流程」一节(11-24);单独改一个重要屏、勾哥没说简化时仍走完整三路。persona 只看图和文字，用便宜的模型;UI/UX lead、主美、合成留在主力模型。AI 扮的玩家擅长挑出看不懂的字、找不到的按钮、断掉的转化，预测不了真实付费意愿;付费相关的判断留给勾哥。
