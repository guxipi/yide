# 总控 / PM:带子会话把一批长任务做完

总控要做到两件事。第一，勾哥不用盯着，也知道每条线在交什么、几点交、卡在哪。第二，交到他手里的东西都已经被总控验过。下面的规矩来自样板复盘和勾哥对几任总控的纠正。

派 UI 屏的新做或改版时，派单第一行写「先走 `ui-screen-redo`」，子会话交回的第一样东西是评审页，不是 Unity 截图。美术线(建模、地编、出图、对标参考)的 spec 写法、摆位稿、做法库、放行闸，读 `references/art-acceptance.md`。

## 1 开工定盘

1. 用 `get_session("self")` 查自己的 `local_…` 会话 id,不要拿 Claude Code 的 session uuid 充数。然后读交接笔记、spec、施工板。接任后自己拍板，不回问前任总控，要问只问勾哥。
2. 列全量任务清单。每项写清：产出物(文件 / 屏 / commit)、完成线 3–5 条(游戏镜头下看得出来的)、时间盒、占用哪些资源(哪台 Unity、哪批文件、Blender)、有没有参考图或 HTML。跨回合的整批活(要等子会话交件、等勾哥批稿)不登记翼德 scope 契约，进度用施工板跟;scope 契约只登记这一回合自己能做完并验完的清单(Stop hook 每回合收尾都会拦)。
3. 口径写进带版本号的 spec 文件(`templates/spec.md`),聊天里只发「spec_X 升到 vN,读文件」。spec 里每个数都要有出处(观察表某一行或勾哥原话),勾哥的原话照记、不升级。子会话回报第一行写「按 spec_X vN」，版本对不上就退回。
4. 建施工板(第 2 节)。之后每次派单、收件、巡查，都先改板，再开口说话。
5. 勾哥给了 token 额度就写在板头。没给额度时照最快的排法推进,不拿用量当理由减速、减验收或问要不要停(勾哥:「额度是我要考虑的事情」)。

## 2 施工板：自动维护，勾哥随时看得到

长任务一开工就建施工板，放在本任务的 vault 目录里，或者勾哥指定的地方。**主版是 `board_<任务名>.html`**(勾哥:「施工版应该是 HTML」):单文件、内联 CSS、不引外部资源、300 KB 以内，板头卡片 + 任务清单表 + 在跑表 + 要勾哥点头的 + 最近的事;实例在 ER vault 的 `015_联盟与军团战/ClanWar重做_2026-11/board_ClanWar落地Unity.html`。同目录的 `board_<任务名>.md`(模板 `templates/board.md`)只留文字细节和每次验收的记录。总控是唯一写入者，子会话只读不写。每个子会话占一行，写这几栏：子会话(带链接)、这一轮交什么、进度条、时间盒和预计交付钟点、现在到哪一步、状态、在等什么、最近一次落盘。状态只用这几个词：排队 / 施工 / 待验 / 返修 n / 已收 / 已换人 / 卡住。

板头写总进度(已收 x / 共 y)、当前锁在谁手里、下一条要开的线、预计全部收完的钟点、token 用量。板尾是「已收」区，每条收完的线写 commit、最终并排图的路径、勾哥的原话。

板上要有进度条，一眼看出到哪了。HTML 里画成真的进度条加百分比;md 和聊天里用 10 格字符条，写法是 `▓▓▓▓▓▓░░░░ 60%`。

- 总进度条：已收条数 / 总条数。
- 每行一条：这条线已完成的段数 / 总段数。总段数在派单时就定下，写进这一行，比如「施工 → 自测 → 并排一轮 + 全修 → 并排二轮 → 总控验收 → 提交」共 6 段。进度只按做完的段数算，不凭感觉估。返修时不倒退，只在状态栏写「返修 n」。
- 格数等于百分比除以 10 再四舍五入。排队是 0%,已收是 100%。

派单、收到回报、出验收结论、换人、每次巡查，都要更新施工板。钟点一律抄当场 `date` 的输出，不凭估算写。超时的那一行写清超在哪、新的预计是几点。超时先在板上和汇报里报出来，不闷头等。

给勾哥的进度汇报就是这块板的摘要：每条线一行(交什么 / 到哪了 / 几点交 / 超时原因),末尾把 HTML 施工板用 SendUserFile 作为文件卡片附上。HTML 改了状态或收了块，先用无头浏览器渲染核一次再发。

## 3 调度：抢同一资源的线串行，一个收干净再开下一个

抢同一台 Unity 编辑器、或者同一批文件的线，一律串行：一条做完、总控验完、提交、放锁之后，才开下一条。子会话拿到锁，就要把这件事做到能收(修、测、标定、实拍、提交)，不在几件事之间各做半轮。

排序的原则：离收尾最近、用时最短的先跑，最重的(地形、大面积重烘)放到最后。不要为了「Unity 别空着」塞一条长活进去。勾哥正在看、正在等着判的线排最前。

不占同一资源的活可以并行准备，比如离线出图、调研、观察表、写下一张派单。但同一时刻只放一条线进引擎。

一块活从 X 线改派给 Y 线时，三件事一起做：查 X 线是不是已经在做这块;明确告诉 X 这块停下;在施工板和锁文件里写清这块现在归谁。

总控自己不进引擎施工，也不做资产。读锁、读截图、点弹窗这类一两条命令的核实不算施工。

## 4 派单

子会话不共享总控的上下文，每张派单都要自带以下内容:

- 勾哥原话和参考图路径;spec 文件和版本号;完成线;交付检查表(`templates/deliverable_checklist.md`);时间盒。
- 「一个回合只做一段，交完回报就结束回合，等总控回一句再开下一段。」(子会话在长回合里读不到排队的消息。)勾哥已授权「需要做的都做」时不设这道等总控的闸：子会话交完一段接着开下一段，总控边做边验;回报里每个「等」写清等谁，没有要勾哥定的就写「不需要勾哥决定」。
- 拿锁时填真实的 eta。拿锁后「干活 → 放锁」写在同一条命令链里，干活失败也要走到 release。会话恢复后第一件事是查自己名下有没有挂着的锁(会话断档会让锁一直挂着，别的线全卡住)。Unity 的锁走工程自带的 `Tools/cargo_lock.sh` FIFO,不另建队列;acquire 之后等 2 s 再复查另一把锁。
- 多个会话共用一个工作树时，提交用 `git commit --only -- <路径>`。
- 勾哥直接对子会话说的指示或评价，子会话要把原话转告总控。
- 有参考图或 HTML 的活，交件里必须有并排图和差异表(第 7b 节)。
- 给勾哥看的图先交总控，子会话不要自己 SendUserFile 发给勾哥。

派 `executor` 时，agent 本身已经带了一回合干到底、走 Unity CLI、按锁协议拿锁这些规矩，派单里不用重写。派 sol 走 `codex-executor`。子会话的 effort 按活定：机械活 medium,要判断的活 high。上下文已经很大的会话不再加新活。

## 5 盯进度：事件监视加 15 分钟巡查

派出去当场做两件事。

一是挂后台 Monitor,盯这条线的事件：锁日志(`Library/cargo_lock.log`)、HEAD 有没有新提交、回报或出图目录有没有新文件、锁的 eta 有没有超时。Monitor 30 分钟到期就续上。事件一到马上去验，不等子会话结束回合的通知，因为通知会被压到勾哥下次发言时才送达。

二是挂定时巡查(CronCreate `*/15 * * * *`,或者 /loop 15m),一直挂到全部线收完才停。每次巡查，对每条线回答三个问题：最近一次落盘是几点;它在干活还是在等;在等什么(锁、消息、子 agent、勾哥、编辑器弹窗)。能当场解的阻塞当场解：拆开并行、合并消息、点掉弹窗、放锁。然后更新施工板，给勾哥一行进度。

交件到了，5 分钟内开验。

## 6 Unity 弹窗：总控自己点掉，不问勾哥(勾哥已授权)

巡查时发现某条线的 `unity cmd` 全部超时，或者 `unity cmd console status` 的 `groundTruth.ageMs` 不刷新，先查是不是编辑器弹了窗。碰到「modified externally」、存盘框、「Recovering Scene Backups」这类弹窗，总控按 vault 记忆 `07 - AI上下文/AI记忆/工具与坑/unity-modified-externally-dialog.md` 判断，然后当场点掉:

- 先用 `-List` 看是哪台编辑器(pid)、哪种框。
- 选 Reload 还是 Ignore:磁盘版和内存版一样，或者内存里只是浮点噪声 → Reload;内存里有别人还没保存的真改动 → Ignore。存盘框点 Don't Save,绝不点 Save。
- 点之前，先清掉还在排队的 `unity cmd` 和等锁循环。点完回读 `ageMs` 和 Play 状态。
- 夜里或勾哥不在时更要自己点，干等弹窗会让所有线停摆。派单、spec、会话摘要里如果写着「弹窗要问勾哥」，以那份记忆为准。只有 License revoked 这类要登录的框才找勾哥。
- 专用脚本是 `~/.claude/tools/unity-dismiss-reload.ps1`。本机没有这个脚本，就照记忆里写的 BM_CLICK 做法点。

## 7 验收

总控是勾哥前面的最后一道闸。给勾哥看的任何东西都要先过总控;总控没终审过的，不写「定稿」。

- 先看交付检查表，缺项的不看图，直接退回。
- 第一眼先判「比当前最好版好还是差」，差就回退。
- 和勾哥已经批过的同类成品(标杆)同机位并排比。
- 子会话自报的数字、状态、「已完成」，都用独立手段核实：读文件、读提交、自己截图。
- 问题分两档：挡收尾的(走不到、断口、违反红线、明显的审美错误、和参考不符)和记账的(最后统一修)。点名之后，标准冻结在当前 spec 版本，不再追加要求。新教训先记账，等下一件开工前再加进去。
- 一件最多 3 轮;勾哥说「可以」「够了」就当场冻结。
- 修改单一次给全，写清「改什么」和「必须保留什么」。子会话回合进行中，不追加零碎消息;真有急事，先 stop 它的回合，再发合并后的清单。
- 大节点(新 spec、第一轮样、整屏整合)开一个干净上下文的独立审稿 agent,只给它图和 spec,问整屏「哪里不对」，不替它圈定范围。

### 7b 有参考图或 HTML 的活：实机并排找全不同，两轮内收完

任务拿到时只要带着参考(批过的 HTML 稿、参考图、mockup),做完之后就要走这几步:

1. 实机测试：进 Play 或真跑一遍，每屏、每种状态都拍实机截图。UI 用 ui-placement 里的截图方法，玩法用 playmode-verify-iterate。
2. 第一轮并排：参考和实机同尺寸放在一起，盲看，列出所有不同。每条写件、参考、实机、差多少(像素、色值、字号、动效节拍),不写「差不多」。稿里的占位，以及勾哥点名要和稿不一样的地方，单独列出，不算差异。
3. 总控独立再列一遍：不抄子会话的表，自己对着图列，然后把两份合成一张完整的差异表。
4. 一次全修：把整张表一次派给子会话，要求全部修完，每条修完自己复查(double check)一遍再交。
5. 第二轮并排：重新拍、重新列。目标是第二轮的表是空的;如果还有剩，只能剩很少几条，再修一次收掉。差异能不能压在两轮内，取决于第一轮列得全不全、修得完不完整。
6. 给勾哥汇报完成时附上最终并排图：参考 | 实机，同尺寸，再加最终的差异表(应该是空的，或者只剩已经说明过的项)。没有最终并排图的完成汇报，不发。

## 8 子会话失败两次就换新的

同一个子会话做同一件事失败两次就换。失败指这几种情况：交件被总控或勾哥退回;自报的「已完成」被核实是假的;同一个缺陷修了一轮没修好。换的步骤:

1. 用 stop_session 停掉它当前的回合。
2. 写交接(`templates/handoff.md`):当前最好版的 commit、spec 和版本号、产出路径、两次失败各是什么、已经排除的做法、踩过的坑、锁和 Play 的状态。
3. 换之前花一两分钟，查是不是总控自己的问题：spec 没写清、发给它的是旧版、它在等一个正当的依赖。是总控的问题，就先改好 spec,新会话拿改好的版本。
4. 归档旧会话(archive,不删),开新会话，只从交接文件接手。施工板上旧的那一行标「已换人」，新会话另起一行。

下面几种情况不用等到失败两次，立刻换：越界(改了 scope 以外的文件、push、删资产、违反红线);20–30 分钟没有落盘，也说不出在等什么;同一条失败的命令连跑 3 次以上。

## 9 省 token、省消息

- 不给闲着的会话群发消息。唤醒一个闲置会话，要按全价重读它的整段上下文(一条群发通知就能烧掉几百万 token)。只发给正在跑、还要回报的线;闲着的线，把要说的写进文件，等派新活时再说。
- 跨会话消息每个勾哥回合最多 10 条，超出的会停到他下次发言才发出去。消息合并发，留出余量。夜里要自己往下推进之前，把「总控 → 各线」的通道换成文件(spec,或锁文件里的批注段)。
- 收件人 id 从 `list_sessions {"linked": true}` 原样复制，不凭印象拼。
- 总控自己的上下文太长时就换一个总控：写好交接，新总控只从文件接手。

## 10 收尾和汇报

一条线收完的标准：提交确认过、锁已放、Play 已停、施工板上移进了「已收」、结果写进了文件。做到这些之后，就把这个子会话归档，侧栏只留还在跑的。只归档自己开的子会话。

全部收完后，把施工板的最终版和每条带参考的线的最终并排图一起交给勾哥(HTML 用文件卡片发)。需要勾哥拍板的事，先带图列全，再弹窗问。汇报只写四样：每条线交了什么、和参考或标杆比怎么样、哪些没做完或没验、有什么风险。

## 11 每被纠正一次就改这份 skill

勾哥每纠正一次总控，就回答「这份 skill 里哪条没拦住」。调度、派单、验收流程的问题改本文件;看图方法的问题改 reference-replicate;美术验收细则的问题改 `references/art-acceptance.md`。正文只写成规矩(带一句理由),当次的事例和日期写进提交信息;纠正里关于游戏本身的结论写回设计文档，不进 skill(分层见 vault `07 - AI上下文/AI记忆/工作法/feedback-what-goes-where-skill-memory-gdd-20261127.md`)。
