## 原理
在 Blender 里把模型按固定视角正交渲成"画布"(只有固有色 Emission,不乘 AO、不打任何光,纯绿底)→ sol 在画布上原位干净上色 → 配准回画布 → 按材质锁色 → 每个面挑最正对、看得见它的视角,把画投影回 UV → 每类物件出一张图集。

上色单(11-07 起派 terra)**默认只喂一张图 = 本张画布**(在它上面原位改,版式不动;N = 1,写进 `refcount_<set>.txt`)(11-09 晚 LOG / 勾哥选 B「要体现参考图里得质感啊」起可选加喂 `prompt.card` = 本件自己的拆件图 / 设计格格子当 image 2,只学表面质感(渐变多柔多大、亮带多宽),提示词写死不学形、色、色调、光影,画完照常 hardhue 锁色相;这时 N = 2。mo.co 图仍然一律不喂)。11-09 晚勾哥:喂了 mo.co 清透感三张的 WS2 版本带出紫调 / 粉调,「不要给 paintover 生图的时候喂 moco 的图」「参考图什么色,paintover 就应该是什么色」;拆件图 / 设计格默认不喂(自带暖粉会被学走),要喂只走 `prompt.card` 当质感参考。清透感画法写成文字在提示词里,颜色就是画布上的颜色(= 无 hue 概念图本色)。发光件写进 `prompt.lights`(哪些件发光、什么颜色),不写就按 colors 里标 glow / light 的件。

**ER 的游戏镜头不转**(V5:从南 46° 俯视)。所以主视角就是"游戏镜头方向的正交视图 G",再补 E/W 侧视(0.6 倍密度,只在屏幕边缘斜着看到);朝北的面永远不上屏幕,不画。这样画的正好是玩家看到的那一面,张数也只有六面全画的一半左右。

## 五步(脚本在 `scripts/paintover/`)
```bash
B="<blender.exe>"; S=<yide>/skills/er-blender/scripts/paintover; W=<工作目录>; CFG=<配置>.json
"$B" -b <场景>.blend --factory-startup -P $S/po_canvas.py --python-exit-code 1 -- --cfg $CFG --out $W     # 1 底稿
py -3 $S/po_prompts.py $CFG $W                                                                             # 2 提示词(末行打出每单参考张数 N,也写进 refcount_<set>.txt)
cat $W/joblist_<set>.txt | xargs -P 4 -I{} bash <yide>/skills/er-shop-mkt/scripts/run_codex.sh $W {} $N # 2 sol 上色(放进一个 run_in_background)
py -3 $S/po_register.py $W --set <set>                                                                     # 3 配准 + 门(绿色 / 黄绿物件加 --strict-key;稀疏侧视 ECC 发散加 --identity)
py -3 $S/po_hardhue.py $W <sheet> ...                                                                        # 3.5 硬锁色相:轮廓内 a/b 换回底稿、保留 terra 的 L(质感);`--lock-l` 连 L 一起换回 = 整块平涂;和底稿差 > 24 的(本模型的灯)保留。旧的 po_colorlock(按类锁到 palette)不再默认跑,它会在柔光晕里切出楔形硬边
"$B" -b <场景>.blend --factory-startup -P $S/po_project.py --python-exit-code 1 -- --cfg $CFG --work $W   # 4 投影 + 图集
"$B" -b <场景>_painted.blend --factory-startup -P $S/po_review.py --python-exit-code 1 -- --out $W --groups "标签=前缀"  # 5 评审图
py -3 $S/po_board.py <板>.png 2 760 "之前" a.png "之后" b.png ...                                          # 对照板
```

## 配置(样板只有两份:`examples/j01v7_bh_booth.json`(11-04 哨亭干净上色实跑过)、`examples/j01v7_mine_m1.json`(11-05 矿点 M1,带 extra / palette;card 11-09 晚起只当质感参考,样板里没写))
| 字段 | 说明 |
|---|---|
| `set` | 名字;画布叫 `<set>_00.png`… |
| `groups` 或 `group_prefixes` | 一起画、互相遮挡的物件。母舱 = 壳 + 支脚一组;遗址每块残件一组;小件每件一组 |
| `views` | 默认 `["G","E","W"]`;也可以 `S N E W T` 六面正交 |
| `ppm` | 主视角像素密度。V5 实机约 71~77 px/m;J01 用过:母舱 62、遗址 70、小件 110、有顶屋 89 |
| `side_ratio` | 侧视密度系数,默认 0.6 |
| `underlay` | `col` = 顶点色 `Col`(我们 kit 生成的件);`material` = 物件原有的底色或贴图(Tripo 件、外来件) |
| `prompt.what / colors` | sheet 上画的是什么;要保留的固有色(灰写死 NEUTRAL grey, NOT blue/violet) |
| ~~`prompt.style_refs`~~ | 已作废(11-09 晚):不喂任何参考图,写了直接报错退出 |
| `prompt.lights`(可选) | 本模型自己的发光体、什么颜色、**按件的真实坐标写位置**(例:「帽顶红灯,水平居中、离上边约 2/3」);提示词要求只在发光件自己身上画亮芯 + 自身色边,**不往任何别的面染光**(11-10 铁规 0,见 09);独立灯件在墙上什么都不画。不写且 palette 无 `glow` = 本张无光源 |
| `prompt.card`(可选) | 11-09 晚恢复,只当质感参考:本件自己的拆件图 / 设计格格子路径(字符串 = 所有张共用,或 dict 张名 → 路径;相对配置文件或绝对路径),作为 image 2 喂进去,提示词写死只看渐变 / 亮带的质感、不学形和色;要么每张都给要么都不给(refcount 一套一个数);颜色仍写进 `colors`,布局说明写进 `extra`;`card_desc` 仍作废 |
| `prompt.extra`(可选) | `{sheet 名: 一句补充}`,例如「深灰方块是关着的金属检修盖,不是窗」 |
| ~~`prompt.marks`~~ | 已作废(旧做旧画法)。配置里还写着会直接报错退出 |
| `palette` | `{类名: "#RRGGBB"}`,**填从没有 hue 的概念图本色取的色**(11-09 勾哥拍板;白模 Col 也用它);发光件类名写 `glow`(有它且没写 lights 时按默认发光描述)。只有旧的 po_colorlock 需要它 |
| `fallback`、`atlas_scale`、`cut_m` | 第三轮兜底(默认开)、图集缩放(默认 0.75)、长面切段(默认 1 m) |

## 门(全部要过)
1. **terra 门**:`run_codex.sh` 自动核 rollout,参考图张数必须等于 po_prompts 打出的 N(恒为 1)。REJECT 原样重跑一次;连续两次 REJECT 停下查原因。J01 两批 33 张里有 2 张第一次被拦,重跑后通过。
2. **配准门**:`po_register` 判 PASS = 仿射配准后轮廓吻合度 ≥ 0.965,且 Lab 色漂 < 12。J01 33 张实测 0.970~0.999。
3. **内部漂移,必须人看**:轮廓门看不出"轮廓里的东西被挪了"(例如屋顶俯视是个矩形,肋画歪了也照样 PASS)。每张 sheet 和画布上下叠着看一遍。
4. **评审门**:46° 全景、3/4、游戏距离各一张,前后对比;再和 `贴图风格基准/moco清透感_20261109/` 三张并排(只在验收时看,不进生图),逐项写差在哪(色是否干净饱和不发灰、大柔渐变和棱上柔亮带是否像参考图的质感、有没有 AO / 内角或挑檐下压暗 / 投影(有 = 重画)、深色件是否近黑、有没有非几何板缝、发光件有没有亮芯和周围光晕、有没有混进笔触 / 斑驳 / 脏痕 / 冷紫阴影,混进任何一项就重画)。hardhue 后同一面左右两端各取一次色,色相差肉眼可见 = 没锁住;找到一处漂移整个 POI 每类材质一起扫。硬锁后实机增益要重标。有绿色、有品红(没投上的面)、有错位的竖纹 = 回去查,不交。
5. **引擎门**:paint-over 完**直接放进 J01 地图里这个 POI 的实际位置测**(11-09 勾哥:「paintover 后直接放入实际地点测试,而不是再放到某个样板间里面」),不进 HBLab / JungleLab 这类样板间;在实际地点的真光照、V5 镜头下截图(两阶 toon 只是近似 LabLit),周围地面、路、植物和邻居建筑一起入镜。LabLit 只吃这一张底色图。

## 坑(全是 J01 实际踩过的,每条都改进了脚本)
| 坑 | 症状 | 根因与做法(脚本里已处理) |
|---|---|---|
| 一个面横跨多格 | 屋顶出绿块、不存在的肋 | 面的中心落在半格里,两端却伸到别的格。投影前沿世界 X、Y 每 1 m 切开,并要求整个面落在格内 |
| 被挂件盖住角的面 | 货匣端面没上色 | 只要多数采样点可见就算可见,护角盖住采样点后被判成看不见。改成三轮:严格(中心 + 多数角点)→ 宽松(只看中心)→ 兜底 |
| 被前景挡了一半的面 | 门楼发光环被抹到旁边的小面上 | 宽松规则太松。先过严格轮,严格轮挑不出视角才降到宽松 |
| 侧面正好与主视角平行 | 肋旁一条条浅色竖纹 | E/W 视角被相邻肋挡住,主视角又看不到这个面。兜底轮:取最正对视图里投影位置的颜色 |
