# 01 通道与工具:live 用 MCP 迭代,出货用 blender -b

ER 的 Blender 活有两条通道,分工固定:live 通道(Blender MCP)只用来边改边看、单件迭代;出货通道(`blender -b` 后台脚本)负责导入、修改器、烘焙、导出、验收门和批处理。验收证据只认后台渲到文件的对照板加数字,MCP `look` 的截图只算迭代过程。

## 开工前三件事

1. 先调 `get_objects_summary`。连不上就是 Blender GUI 没开、插件没启用或 Online Access 没开(2026-07~10 社区版时期有 13 个会话撞过"连不上",别反复重试);请勾哥开 Blender GUI,或者直接改走后台通道。
2. 官方文档声明代码执行"没有任何防护",LLM 生成的代码能删数据、能联网;不要在 Blender 里开着和任务无关的重要文件。
3. 写 bpy 拿不准先 `search_api_docs` / `search_manual_docs`,不要凭记忆写 5.x 已改名的 API(见 02)。

## 后台通道写法

```bash
F:/Apps/blender.exe -b --factory-startup <file.blend 可省> -P script.py --python-exit-code 1 -- <参数>
```

参数从 `sys.argv` 里 `--` 之后读;`--factory-startup` 不吃本机偏好和插件,结果可复现;设置类参数放在 .blend 文件名后面(打开 blend 会覆盖前面的设置)。脚本异常退出码非 0,外层据此判失败。每个入口脚本只有一个 `main(argv)`,结果打一行 JSON 到 stdout,这样同一个脚本在 MCP 里 `importlib.reload` 后也能直接调。

纪律:GUI 会话和后台进程不能同时写同一个 .blend;**不要关别人开着的 Blender GUI**(误杀过一次,er-vesper-cur-model);重要 .blend 别只留在 scratchpad(会丢)。
