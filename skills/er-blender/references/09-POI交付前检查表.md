## 铁规 0(勾哥强制执行,压过本表其它任何条目)

**生图时画面里每样东西都是它自己的本色。** 楼、屋顶、地面、草、树、岩、水、道具、家具、车、植物,没有例外。灯光、时段、氛围、阴影都不能改任何东西的颜色:不罩整图色调(淡紫 / 暖黄 / 偏蓝都不行)、阴影不带色、发光件只画自己亮、不往别的面染色。风格参考(方向图 / mo.co)只学形、材质和收尾质感,**不学被光染出来的颜色**。外观 / 室内 / 俯视 / 拆件 / 方向图 / paint-over 全部适用。
**少用粉色、紫色**(男性向):固有色里粉 / 紫 / 品红 / 丁香只给极少数功能件,楼体、屋顶、大面积材质不用。
**不许并排多色彩条**(会让人联想 ARC Raiders,有侵权风险):三条及以上不同颜色并排的条 / 块(青 + 黄 + 红这类),柱身、车身、墙、牌子、线路图、导向牌、地面标线都不许;改单色色带,线路图一种主线色 + 站点亮点,导向牌一个色块 + 白箭头。概念图 / 拆件图里有就按本条改,不照图建;工单 AVOID 写 rainbow / multi-colour stripes。
**怎么强制**:发单前跑 `scripts/imagegen/prompt_lint.py <工单...>`(缺本色段 / 出现 lavender、tint、glow halo、purple-grey shadow / 风格参考没写「只学形和质感」→ 退出码 1,不发);图回来跑 `scripts/imagegen/img_colorcheck.py <图...>`(中性面偏色 / 粉紫占比超标 → 退出码 1,不交)。

## 头号教训(这四类各被纠正 3 次以上)

1. **paint-over 只加明暗,不碰色相**。见 §四。
2. **按游戏镜头(V5 46° 俯视)做,不按拆件格的平视做**:玩家看的是屋顶 + 南沿 + 两面外墙;逐件按平视做对、进游戏只剩白盒子的,整个重做过。见 §一、§三。
3. **没把参考看懂、拆清楚就开建**:先拆解单 → 体块 → 叠图,叠图没过不做细节;单件对着拆件格做到像。见 §三。
4. **自己放过可见瑕疵,让勾哥当质检员**:交付前按件类全量过、一个根因全局扫、看见的不放过。见 §六。

## 一、设计(拆件表 / 方案)

- [ ] **按当前地图的 POI 设计口径**(见文首指针)核楼体分类、屋顶、外墙、室内和精英位;口径里没写的先问,不自己编。
- [ ] **方向图不是零件库**:广告屏、灯箱、空调外机、水箱、雪糕筒、灯笼串、条纹布篷这类氛围件,只有本 POI 设计表明列且和地点功能相符时才出现;两个 POI 不共用同一组氛围件。小件 = 本 POI 的职业件(灯塔的浮标 / 系缆桩,矿点的岩芯管……)。拆件表逐件问「这件是方向图带进来的,还是这个地点自己的」。
- [ ] **拆件要多、一眼认得出、外形不雷同**。
- [ ] **按游戏内物理空间设计**:位置、朝向、路口、邻居按实地;外形不必贴现有脚印,放得进 plot、不 awkward 就行。
- [ ] **室内能走能跑**:门洞、走廊、家具间距按 NavMesh agent 半径留足(按会进来的最大体型怪算),家具不堵通路、不穿墙;放精英的房间写清精英放哪、守什么,房间够精英活动和玩家走位。数字门见 §七。

## 二、出图(概念图 / 拆件图 / 俯视图)

- [ ] **四张图**:外观 / 拆件 /(大 POI)内部 + `topdown.png`(游戏镜头竖屏)。拆件图要有一格俯视屋顶。
- [ ] **只画物品本色**(铁规 0):概念图 / 室内 / 俯视不画光照色调,拆件图连投影和接地影都不画。工单里写明风格参考「只学形和质感,不学光色」;`prompt_lint.py` / `img_colorcheck.py` 不过不发 / 不交;带色调的图打回,不从它取色。
- [ ] **不喂旧 POI 图、不喂游戏实拍**:布局用文字写;风格参考只用 mo.co 帧、勾哥给的范本、他批过的方向图;建筑参考用 mo.co 的建筑帧。
- [ ] **提示词写死排除句**:no neon billboards / light boxes / AC units / water tanks / pink car / cones / lantern strings / striped awnings unless listed。
- [ ] **topdown 一眼认出**:每个 POI 从俯视就要一眼看出是什么;辨识物长在屋顶 / 俯视轮廓上,不只挂在立面;盲认闸对 `topdown.png` 单独再跑一次,只看 topdown 说出地点才过,不过就改设计,不是只重出图。
- [ ] **盲认闸(防泄题)**:每个 POI 的图出完,先复制成中性文件名(`img_07.png` 这类)放进不带 POI 名的目录,提示词里不出现 POI id / 中文名,再让没有上下文的子 agent 盲看,第一眼说出是什么地点才过(子 agent 会从文件名读出答案)。说不出 → 先查是不是通用件盖过了职业件,换辨识物重出;重出轮不喂参考图、风格全用文字。过了再出拆件 / 俯视。
- [ ] 已有批过的概念图不主动重出;图和设计对不上先问勾哥改哪边。

## 三、建模(Blender)

**流程**
- [ ] **一轮 15 分钟**(07「小 POI 一轮 15 分钟」):拆解单(每件 `why` / `cell` / 尺寸;`conflicts`、`absent` 写全)→ `blockout.py` → `overlay.py` 俯视 + g46 叠图 → 细节 → 出图。说不出用途的件不建;叠图没过不做细节;超时说卡在哪一步。
- [ ] **目的是单件精准**:每件对着拆件图那一格单独做、单独渲、左右并排;复用件库里没有就照格新做,不放占位块。摆位和概念图的小偏差不纠结,不把坐标同步回设计数据。
- [ ] **植物**按 SKILL.md 路由表(灌木 Blender 逐片叶、树冠 Tripo、地形植物和崖默认在 Unity)。
- [ ] **有机件先做单元**:灌木先交单片叶和参考叶并排,过了再拼环(5–6 片一环绕枝、相邻环错开,顶上 3 片相交)、再拼整丛;成品读起来不能是穹顶 / 球团 / 叶卡糊成一团(用什么做不限,结果要像参考)。
- [ ] 不会建的先 research(液体、凝胶、绳、木),不拿一眼不像的件收工。
- [ ] 面数不设每类硬上限(07「面数」):不为省面降质量、不为凑面数改形砍件。

**墙与结构**
- [ ] 每个凸出物说得出用途,说不出删。
- [ ] 与平台同高的那级踏步并进平台;楼梯上不许有接缝。
- [ ] 倒角和圆润度按 00(宽而克制,不比 mo.co 更圆、更软糯)。
- [ ] 部件相交处有过渡,读成一个整体,不读成盒子贴盒子(07 做法第 7 条)。

**屋顶**
- [ ] **平顶不做夹心饼干**:屋面色从边到边铺满整个顶面,墙顶不另起一圈压顶色;顶棱只留一道窄硬斜棱(同屋面色),不做大圆角带(在强受光下会削成高光带)。南沿雨棚 / 挑檐 / 灯盒离檐口 ≥ 0.4 m,读成门头不读成又一层屋顶。拆件格里画的大圆角顶棱照这条改。
- [ ] **屋顶植被只用立体件**:叶团、垂藤、真有体积的堆;不贴平面苔斑 / 污渍片 / 扁盘(实机读成「绿色的土」「平橙盘」)。屋顶不单调靠本职业设备件,不靠给屋面分层或描边。
- [ ] **屋顶细件(管、筒、杆、灯杆)进引擎关投影**(`shadowCastingMode Off`),否则屋面上压出一道道影条;大体块照常投影。小件别落在大件投影里。

**件**
- [ ] **先做形体拆解再建**(勾哥:「该是什么形状就是什么形状,不要拿盒子凑,也不要让人看出来这个是方块切割出来的」):每件拆成真实零件,每个零件写「真实是什么形 → 用什么做」——转出来的(壶、碗、罐、旋钮、阀体、脚)= 旋转体;弯出来的(拉手、把手、管、龙头、扶手)= 沿曲线扫的管;板 / 柜 / 门 / 台面 / 机身 = 圆角轮廓挤出 + 圆棱;坑 / 槽 / 洞 = 圆角或圆形轮廓布尔切(不用方盒切);软的(毛巾、被子)= 截面挤出带垂坠;贴纸 = 认得出的图形。说不出零件名的块不建。样板函数在 Extraction `ArtWork/J01v7_BIO_20261111/gen/bio_common.py`(`bar_pull` / `knob` / `panel_door` / `cut_prism` / `sticker`)。
- [ ] **拉手照真实家具做**:D 形弯杆(管径 ≥ 3 cm、两头圆立脚)或圆旋钮;不用「大块浅色方框 + 内凹芯」那种方块拉手。
- [ ] **要有弧度和圆角**(勾哥:「我们的东西太方了」):柜体 / 门 / 台面 / 电器的棱和角都圆,倒角按 00,仍不比 mo.co 更鼓;套 mo.co 手法时守住「认得出」那条结构(平顶的东西不出檐,冰箱加出檐顶板会读成床头柜)。
- [ ] **有门 / 有盖的件和桌子都能打开**(SKILL.md 工作纪律):门扇 / 盖子 / 抽屉单独成件、轴心在铰链、墙上开真门洞、箱子做空心;出关 / 开两态,开态内部也上色;拆解单里标「容器」。开盖箱的盖要有真实结构(托盘盖 + 铰链);筒形建筑内部空心可放东西。
- [ ] 绳、木头靠纹理读:绳画几道宽扁的股纹块,木头用几道顺纹的宽扁短条、端面两三圈宽年轮表达(不画细密木纹);不做细直管 + 顶点色格子、不做平涂圆柱。
- [ ] 楼梯 / 栏杆 / 细杆斜放件:整件灰钢顶点色,不进 paint-over 投影;开口踢面透出地板也算错。
- [ ] 家具和地面拉开明度和色相。
- [ ] 花坛石圈整块连续(下段墙 + 外挑压顶),不切砖、不做砖缝。
- [ ] **改岩块造型前先拿单件图问勾哥**。
- [ ] 散件不 AI 排布:不等距一条线、不对称扇开,要像人手放下 / 自然长出。
- [ ] 小件不因「实机才 20 px」简化建模或跳过上色。
- [ ] **小件逐件和参考格并排 + 写不同点**(只管小件,楼体按坐标 / 平面,不逐条比):同角度、中灰底(白件要看得清),结构先写(由哪几部分组成、数量、弯扭方向、支架怎么接、比例),每条标 已改 / 故意不同 / 待改,不许写「基本一致」。
- [ ] **单件盲认**(勾哥:「这种看不出来是什么的不应该给通过」):每件单件渲图改中性文件名,给没上下文的子 agent 只问「这是什么物件」,说不出 = 重做;盲认原话写进清单。总控审板先遮标题自问「这是什么」。

**出图核**
- [ ] 建完先出 Blender 游戏镜头 46° 图看屋顶和两面外墙,再出拆件格角度的并排。

## 四、上色(paint-over)

- [ ] **画法 = `00-造型与笔触标准.md` 第二、三节**(基准图 vault `013 美术/mo.co截图/车辆语言基准_20261127/`):干净固有色上加少量宽扁、不透明、边缘清楚、顺结构的手绘块面(斜矩形、楔形、短条、局部面状提亮),大量安静区域,哑光;同一大面允许局部硬边笔触;只动同色相明度。不画 AO / 内角 / 挑檐下压暗 / 投影 / 方向光 / 环境色;不画刷毛、厚涂、乱线、密集划痕、做旧,不给每条边描亮线;面上不画非几何的缝 / 网格 / 石缝。
- [ ] **生图喂什么**:image 1 = 底稿(颜色只认它);可加 `prompt.card` = 本件拆件格(只学笔触位置和疏密)、`prompt.style_refs` = mo.co 笔触参考(只学笔触形状、大小、疏密和形体语言,不学色、色调、光照、环境色)。N = 1 + card + style_refs,画完必跑 hardhue 和 `img_colorcheck.py`。
- [ ] **参考图(无 hue 概念图)什么色,成品就什么色**(不调色相、不整体加深加饱和);提示词写死「image 1 的颜色就是批过的颜色,不加紫 / 粉 / 暖 / 蓝偏色」;浅低饱和色(混凝土)写 COLOUR LOCK + 色值。
- [ ] **画完跑 hardhue 纠意外色漂**:`scripts/paintover/po_hardhue.py <work> <sheets>`,轮廓内逐像素 a/b 换回底稿(多色分件照留)、保留画上去的明度(笔触);和底稿差 > 24 的(本模型的灯)保留;`--lock-l` 会抹掉笔触,只在笔触画坏时用。锁过色相不等于画风达标。硬锁后实机增益重标。
- [ ] **重画 / 重配准后先删 `reg/<sheet>_prehue.png`**:po_hardhue 会沿用第一次留下的 prehue,不删就是拿旧画锁色相。
- [ ] **验收不只看平均 hex**:同一面左右两端各取一次色,色相差肉眼可见 = 没锁住。找到一处漂移,整个 POI 每类材质都扫一遍一起改。
- [ ] **不画环境光**(铁规 0):extra 开头写 NO ENVIRONMENT LIGHT,点名本 POI 仅有的发光体;**不往任何别的面画光晕**,其它件逐个点名「只保留固有色和笔触块面」。
- [ ] **发光件在 paint-over 里只画它自己**:门边灯条、路灯头、广告牌、屏、亮窗——亮芯近白 → 自身饱和色边,画在发光件自己的面上;**不往墙面 / 地面 / 邻件画光晕和光池**,周围的光交给 Unity 的灯和 emission。独立发光件写「它是单独物件,墙上不画它」(否则双灯带)。小发光件单开高密度 set(420 px/m)。
- [ ] 灯色(蓝 / 琥珀)不涂成固有色;盖子里面和盖子同一种灰。
- [ ] **玻璃**(11-27 勾哥):不用「深蓝底 + 两根平行斜亮条」的符号画法(读成贴了反光图案的金属板)。底色取中明度的设计固有色、和窗框拉开,玻璃略内嵌于有厚度的窗框;反射用少量宽大、低频、面状的明度变化,同一立面相邻窗格共享连贯的反射关系(按世界坐标沿立面铺,不逐窗复制),不同朝向的窗面强度不同;环境反射和染色交给 shader 或受控遮罩,不把彩色反光条烘进底色。不强制透明。验收把全部玻璃件裁成一张板逐块看。
- [ ] 木头:每块板一个平色 + 少量顺板方向的宽扁块面笔触,板缝用几何,不画细密木纹和木节;按材料出质感:布像布、木头像木头。
- [ ] terra 乱画的三种 sheet 在 extra 写死(稀疏 sheet 另画拆件图 / 俯视大平面画上整个塔正面 / 柜背板补画隔板和货)。
- [ ] 细件投影后评审图不许有绿(残绿用 Extraction `ArtWork/J01v7_WS2_20261109/gen/po_degreen.py` 去,这个脚本还没收进本库)。
- [ ] **不给每条棱描亮线**:棱边提亮只挑少数顺结构的几段画成短条块面,屋顶顶棱默认不画(提示词 `edge_rule` 写死「不画亮带 / 暗线 / 边框」)。
- [ ] **投影后跑归属检查,防串色**(勾哥:「这些地方应该都是实体墙,不要出现这些乱七八糟的纹路」):游戏里会隐藏的屋顶 / 迎镜侧墙,连带藤蔓、吊车环、天窗灯,挡在实体墙前会把颜色印到墙上。跑 Extraction `ArtWork/J01v7_HB_v2_20261107/gen/hb_po_owner.py` → `hb_po_bleed.py --fix`(实体面被别的颜色族占 > 8 % 退顶点色,外来颜料按同组回填;这两个脚本还没收进本库)。
- [ ] **上色后小件再和参考格 1:1 并排**(勾哥:「paintover 之后更要和参考图一起 1:1 对照」):带贴图的单件同角度、中灰底,和拆件格并排,逐条写不同点——每块材质取色、色块边界错位 / 拉伸 / 串色、腰线 / 窗 / 屏 / 标识位置、玻璃、质感、多出来的笔触或光晕。没有这张板不装机。
- [ ] 提示词发出前对一遍现行铁规(旧要求和新铁规冲突以新为准或先问)。
- [ ] 上色派 terra,不派 sol(勾哥按成本定)。

## 五、进引擎实地

- [ ] **先删旧 POI 整个根,再放新的**;旧根上的搜点(loot prefab)不跟着删,在新件位置重新挂上、隐藏网格。
- [ ] **直接放进游戏地图里这个 POI 的实际位置测**,不进样板间。**在别的空地 / 原点 / 临时坐标先试组装一遍再搬到真实点位,也算样板间,不做**:第一次进引擎就装在设计坐标上,拼装核对在 Blender 里做完;实际地块有别人没提交的改动或拿不到锁,报总控排,不自己绕。
- [ ] **Play 里让玩家和怪在室内真走真跑一遍**:每个房间、门洞、楼梯走到,怪追得进来、不卡不穿模;每个容器真开一次。拍图前先开无敌(`DebugTools.GameDebugCommands.GodOn()`,回读 `Health.IsInvulnerable`)。

## 七、装机 nav / 材质硬口径

> **门洞宽高 / 墙楣 / 小房间被剪 / 梯宽 / 门口净区 / 精英位 / 入口连通用共用闸门判,数字只在 `scripts/gates/thresholds.json`**:装机前 `scripts/gates/poi_nav_gate.py` 用导出 .blend 离线跑,引擎烘完 `scripts/gates/navdump_reach.py` 读 navdump 再跑;离线闸门不过不申请工程锁。每个 POI 写一份配置,`ignore_regex` 照抄自己安装器的 nav ignore 名单。见 `scripts/gates/README.md`。

- [ ] **门**:含暗室 / 只进玩家的门(玩家和怪走同一张 NavMesh);门洞高等于 agent 高时体素取整过不去,按 thresholds 留余量。门不超墙高:门洞顶到墙顶留墙楣,矮墙上开门就加高墙。
- [ ] **小房间**扣 agent 半径收缩后净面积要过烘焙 minRegionArea,否则整块被剪(暗室、卫生间最常中)。
- [ ] **梯宽**:墙间梯进烘焙后会被两侧各扣一个半径,窄梯会只剩一条缝。
- [ ] **门口家具净区**:门洞两侧都查,**挂墙件(板 / 屏 / 架)不许跨门洞**,按门洞全高查。
- [ ] **精英位**离最近边按 thresholds;房间达不到就不放。
- [ ] **跨构件的同色带(檐带 / 踢脚 / 压顶)整条走同一条管线**(顶点色或 paint-over 二选一),否则出分界线。玻璃厚度面 / 窗台面用框色,不用玻璃材质。
- [ ] **揭顶剖面**:截面实心(别用 bisect 补面,C 形环会判错),封口整圈墙顶同色。
- [ ] **从每个入口 CalculatePath 到每个房间 / 每层 / 每个精英位 / 屋顶全部 PathComplete,navdump 三角连通块只有一块**(逐门全通也可能有整块孤岛、整层上不去)。门洞净宽 / 净高从该层地坪量。
- [ ] **逐门探针按门扇包围盒底取样**,结论和 navmesh 俯视图对一眼再报。室内追逐用站内精英位验,站外引怪只当参考。
- [ ] **工程锁**(协议见工程 `CLAUDE.md`):一个 POI 拿锁前离线全做完(安装器离线编译 0 错、量数全过、目标色已取),拿锁后同一把里做完不中途放锁;锁外不碰共享 bake / region 目录;还原只还原自己生成的文件,不对整个 chunk 目录 git checkout。
