# 07 建筑与联邦小件:先做部件,再按设计坐标拼

POI 建筑在 Blender 里做(勾哥定):先拆成墙、门框、屋顶、壳段等部件,再组合起来;建筑直接落在地面上,**不做地板**(也不做印章基座);部件库 Claude 直接做,不派 sol。

脚本在 `scripts/kit/`(全部 `blender -b --factory-startup -P <脚本> -- 参数`)。它们是首批 POI 的生成器,换场景照着改参数或抄结构,不要从零再写。

| 脚本 | 做什么 |
|---|---|
| `kitlib.py` | 调色板(默认是首批联邦件的配色,新场景按设计换)、`Part` 拼装器(盒、挤出截面、环、柱、拱顶截面)、倒角(Bevel 2 段 + harden normals)、顶点色 `Col`、布尔切口 |
| `build_sc.py` | 有顶屋:按 `pilot.json` 的墙段、门洞、房间、家具坐标拼整栋;分 Low / Up / Roof / Doors / Furniture 五组 |
| `hull.py` + `build_hulls.py` | 破损横卧舱生成器(穿行通道、两端破口、无顶、高壳留远侧、侧翻变体) |
| `build_ruins.py` | 遗址残件直接按设计多边形原位生成:横卧舱残壳条、立筒半壳、平台残脚板 |
| `props.py` / `furniture.py` / `build_props.py` | 联邦小件和室内家具,尺寸从组件表读 |
| `review.py` / `board.py` | 两阶 toon 评审出图、对照板 |
| `closeup.py` / `solo_view.py` | 按参考角度出同一区域的放大图 / 单件单独渲 |

## 概念图 / 拆件图一律物品本色,不画光影和 hue(铁规 0,勾哥强制执行)

范围是画面里**全部物体**(楼、屋顶、地面、草、树、岩、水、道具、家具、车);风格参考(方向图 / mo.co)只学形、材质、收尾质感,不学被光染出来的颜色;**少用粉 / 紫**(男性向)。发单前 `scripts/imagegen/prompt_lint.py`,回图 `scripts/imagegen/img_colorcheck.py`,见 09 铁规 0。
- **概念图**(外观、室内、俯视):每个件画它自己的固有色。不画方向光、投影、夕照、天光、氛围色罩、整图色调,草、地面、岩石同样不许被染色;体积只靠同色相的轻微明暗。发光件只画灯本身亮着,不往周围染色。
- **拆件图**:全部本色平铺,中性白 / 浅灰底,不打光、不加 hue、不加阴影。一格一件,看得清形和固有色就够。
- 出图提示词(派 codex / sol)里写死这两条,并列进 AVOID:`lighting, cast shadows, sunlight, sunset, colour grading, tint, hue shift, atmosphere, ambient light, glow spilling onto other surfaces`。
- **为什么**:场景的光和色调全在 Unity(LabLit + 场景光 + 后期)里给;概念图带了 hue,建模取色和 paint-over 取色都会把这层 hue 烤进贴图,进引擎再叠一遍就脏、就偏色。
- **验收**:拿到图先 `refkit.py color` 抽几个件的受光面和背光面,同一件两处色相差 > 10° 或整图偏一个色相 = 带了 hue,打回重出,不拿它取色。
- 已有带光影的旧概念图:建模和 paint-over 取色时只取件的固有色(亮面去掉 hue),不照抄图上的色调。

## 做法
1. **先读三样**:设计数据(房间、墙线、门、组件尺寸和坐标)、过审概念卡、mo.co 参考(按 vault `013 美术/AI记忆/现行口径_参考与工具分工.md` 第二节取本物件锁定的图;提取写进工作目录 `notes/`)。
2. **设计数据和参考图不一致时,默认以设计数据为准**:尺寸、高度、比例、房间、门、组件坐标都按数据;参考图只管数据没写的造型和画法。勾哥可以按次改为以概念图为准,单次决定不当新规则。设计数据自己前后矛盾时才问勾哥。
3. **部件分组按游戏行为切**:进屋揭顶时要隐藏的部分单独成组——墙和门框在揭顶高度(以当前设计为准,首批是 1.2 m)处拆成上下两件,屋顶单独一组;进屋时隐藏"屋顶 + 揭顶高度以上"这两组。关闭的门板单独成件。
4. **落地不做地板**:墙和脚墩向地下多伸 0.3 m,防地形起伏露缝。
5. **大门放不进低檐时做"人口"门楼插件**:凸出墙面的门楼块,用布尔把拱顶在通道处切开。
6. **画风**(按 `00-造型与笔触标准.md`):少量敦实主形体 + 粗壮附件,面中心平、转折明确;倒角约为短边的 4~6% 起步,主形体可更宽,不把面鼓起来;三级细节稀疏;靠分块缝、腰线、压顶读结构;缝的底色要浅,深色缝在游戏距离下会读成黑描边。
7. **部件拼完要读成一个整体,不许有拼接感**:件和件相交处(檐口和墙的转角、门头牌和墙、窗台和墙、店面框落地处、相邻店的门边)要有过渡——同一网格挤出或布尔后统一倒角、接缝压边,不是一个盒子贴在另一个盒子上。脚本拼基元 + 平色顶点色在城市楼上被勾哥判成「几个物体拼凑」「像玩具」(11-26);用 kit 拼的件交图前逐处自查这几类位置,按 00 和 mo.co 原图并排判。
8. **出图**:每件出 46° 全景、3/4、游戏距离(屏宽 14 m)三张,橙色 1.52 m 胶囊当 Wren 标尺,和概念卡、mo.co 同尺度拼成对照板,亲眼看过再往下。

## 坑(踩过的)
| 坑 | 症状 | 做法 |
|---|---|---|
| 两个盒子顶面共面 | 顶上出现斜向刻面、闪烁(z-fighting) | 部件顶面错开高度;门楣和门柱不要同时覆盖同一块,门柱只到门高,门楣盖满 |
| 墙段在拐角、T 型交接处重叠 | 交接处闪烁 | 每个端点和交叉点放一根略粗的立柱盖住 |
| 色块抖动按"块序号"取值 | 同一块墙在揭顶高度上下两半颜色不一样 | 抖动按块的平面中心算(z 不参与) |
| 镜头一侧的墙太高 | 挡住后面的设备带 | 镜头一侧的残墙压低;远侧屋顶残片不会挡 46° 镜头,可以放心做宽 |
| 残墙断口用尖锐锯齿 | 不像 mo.co 的块状断口 | 平台阶 + 短斜角,偶尔一个缺口 |

## 小 POI 一轮 15 分钟:拆解单 → 体块 → 叠图 → 细节 → 出图

勾哥要求每个小型 POI 一轮建模 15 分钟以内返回截图。返工的根因不是手慢,是没读懂参考就开建:比例、件数、被挡住的面、多出来的件,AI 看图最不准的就是这几样。所以每轮把"看图"换成能核对的产物,每一步都有命令,不靠眼睛估。

| 分钟 | 做什么 | 命令 / 产物 |
|---|---|---|
| 0–3 | **拆解单**:设计数据(POI 设计 json 的 pieces / geo)抄成 parts JSON,每件写 `name / why(干什么用)/ cell(参考图格号)/ count / shape / at / size / z0`;`conflicts` 写设计数据和概念图对不上的地方(按设计数据做,列出来给勾哥看);`absent` 写参考里**没有**的东西。说不出 `why` 的件不建 | `refkit.py cells 概念图 --n 10 --out grid.png` 打格号;JSON 格式见 `scripts/kit/blockout.py` 文件头 |
| 3–5 | **体块**:只用盒子 / 竖圆柱,每件一个物件 `<id>_<名>` | `blender -b --factory-startup -P scripts/kit/blockout.py -- --parts parts.json --out x.blend`(约 3 秒) |
| 5–7 | **叠图自检**:俯视概念图上核位置和占地,46° 外观图上核比例;叠图偏了当场改 JSON 重跑体块,不等勾哥 | `py scripts/kit/overlay.py --ref topdown.png --blend x.blend --collection <POI>_Blockout --view top --out ov --pts "…" --check "…" --ref-mask "…"`;外观图同样跑 `--view g46`(每张约 3 秒) |
| 7–12 | **细节**:在体块上换成 `kitlib` 正式件(倒角、门窗、栏杆、压顶),只做拆解单里有的 | `scripts/kit/*`、`kitlib.Part` |
| 12–15 | **出图**:发勾哥的只有单件并排板(拆件格 \| 模型);评审图(46° 全景、3/4、游戏距离)和两张叠图板留给自己和总控核对,不发勾哥;整栋等进引擎实拍再发 | `stage.py`;`ov/<label>_top_board.png`、`<label>_g46_board.png` |

**不进这 15 分钟的**:拆解单的盲审 subagent 放后台和建模同时跑(只给概念图 + parts JSON,让它找"参考里有、单里没有"和"单里有、参考里没有"的件),结果并进下一轮;Tripo 补背面只在看不清背面的大 POI 开工前跑一次。超时就说明卡在哪一步。

### 叠图怎么用

- **对应点 `--pts`**:概念图像素 = 世界坐标(米,x 东 y 北,z 可省)。选地面上、设计数据定义了的点:台基 / 地块角、门槛两端、柱脚。2 点相似、3 点仿射、4 点以上单应。**同一张图只标一次**:对应点、`--check`、`--ref-mask` 存在概念图旁的 `<图>.overlay.json`,下一轮只要 `--ref --blend --collection --view --out`。角点先用 `refkit.py sheet` / `crop` 放大到 4–5 倍再读像素。
- **检查点 `--check "名:u,v=x,y,z@fu,fv"`**:u,v 是概念图里这个件的顶(塔顶、牌顶),x,y,z 是设计位置和高度,`@fu,fv` 是概念图里它的脚点。输出:体块投影离概念多远(px、约多少米);≥4 个同高对应点时还会反推概念图相机,给出"概念图把它画在多高 / 画在哪"。
- **读板**:左 = 概念图,中 = 叠体块,右 = 灰底 + 品红体块轮廓(每件单独描边)+ 青色概念主体轮廓;底部是残差、IoU / recall / precision、检查点。对应点残差 > 15 px 先重标点再看别的。
- **概念图透视不自洽**(AI 生成图常见):反推相机残差 > 15 px 时,高度一律标 `UNRELIABLE`,只当"差得多不多"的信号,不当精确数。这时位置和占地以 `top` 叠图为准,比例看 `g46` 叠图;`--view concept`(用反推的概念相机渲体块)只给透视自洽的图用(引擎实拍、Blender 渲染),AI 概念图上会把塔渲歪。
- **俯视图是不是正交先确认**:看板上叫「俯视图」的 topdown.png 如果是 46° 游戏镜头出的,叠图用 `--view g46`,`--view top` 只给真正正交的俯视图。高的件(亭顶、灯头)在 46° 图上有视差,**位置检查点一律标脚点、z 写 0**,量出来的才是纯地面位置差。
- `--ref-mask` 圈的必须是被渲染集合里有的东西:地面没建时圈广场轮廓,IoU 没意义,只看检查点。
- **叠图对不上不等于体块错**:小偏差不纠结、不同步回设计数据(「概念图永远都是概念图」)。只列明显影响玩法的(搜点被挡、走不通、件伸出地块)。叠图的价值在体块比例和件有没有漏 / 多,不在逐米对齐。

### 评审和 kitlib 补充

- 评审图用 Workbench `FLAT` + 阴影 + cavity,才是顶点色本色;`STUDIO` 会把粉紫压成深紫,别拿它判颜色。
- kitlib 有 `vcyl`(竖圆柱 / 圆台 / 圆锥 / 正多边形柱,seg ≤ 12 时平边朝北)、`vring`(竖向圆环:花坛、树池、平躺车轮)、`beam`(两点间定向方条:绳、屋脊、斜腿);`blockout.py` 支持 `shape: cone` 和 `seg`。
- 自查必过:细长件(绳、链)渲出来是不是成了片;屋顶坡度和参考比;件和件有没有穿插(树池压进喷泉);评审图颜色是不是被光压暗。

## 单件精度:每个件对着拆件图那一格做

勾哥定的这套工具的真正目的:单个物品的建模精准、细节还原。

**流程(每件)**
1. **裁格**:`refkit.py crop parts.png --box <这一格> --zoom 3`,再裁场景图里它的位置;两张都 Read。
2. **单件拆解卡**(写进 parts JSON 该件的 `card`,或单独 md):第一行写支撑逻辑 + 功能锚点尺寸(长凳 = 两个支墩 + 横跨的坐面,坐高 0.42–0.47 m、坐深 0.4–0.5 m 是人体尺寸,先钉死,其余比例从它推);再写子件逐条(石墩 ×2、木条 ×4 + 缝、前沿厚木边)、材质、接合(木条插进石墩)、比例、参考里没有什么(无靠背、无金属)。
3. **取色**:`refkit.py color` 每个子件取一次,用亮的那一簇。
4. **建**:每件一个函数,植物用 `plants.py`。
5. **按那一格的角度单独渲**(正交,拆件图约 az −10 ~ −14、pitch 34 ~ 42),透明底,和裁格左右并排;按「形状 → 比例 → 子件数 → 接合 → 颜色」一次列全差异。
6. 两轮没收敛就停,换成量化对位(下一条),不继续凭眼睛调。

**凭眼睛调比例收敛不了**(长凳四轮没收敛:把透视下的端面看成斜面、把「高」看成「深」;每轮同时改尺寸、倒角、相机,前后不可比)。对应规矩:
- 拆件图同一张里所有格是同一个相机(生图一次出的),先标一次相机(拿直角最清楚的件,如长凳、花箱的四个角)并锁死,之后只动模型;宽、深、高三个方向压缩率不同,不拿屏幕像素比当真实比例。
- 平面尺寸用俯视图核;透视有歧义就拿第二视角核。
- 一轮只改一个量。
- 验收看剪影 / 分材质掩膜(按颜色分石、木、叶、花)和渲染的重合度,用搜索拟合尺寸参数代替凭眼睛读;这个拟合脚本库里还没有,要建先问勾哥。
- 植物先做单元库,单元过了再拼件(reference-replicate「先做单元库再拼整体」同理);`plants.py` 是起点。
- 件之间互相独立,可以每件派一个子 agent 并行,主会话只看并排图验收(每个子 agent 带裁格、拆解卡、取色结果和样板函数)。

### 面数

- 不设每类件的硬上限:不为凑面数改外观、砍件;减面不损质量;小超不返修;真机实测卡了再回头减。口径见 vault `013 美术/AI记忆/现行口径_POI建模流程与交付门.md` 第一节。每件出图时报三角数(`plants.tris(obj)`)。
- 花叶满的件压到很低面数会出刻面、叶子成稀疏三角片;要省面就走下一节的高模烘低模。
- 低面数单元在 `plants.py` 下半:`leaf_card`(2 三角)、`flower_star`(约 20)、`dome`、`mound_lp`、`vine_lp`;上半的 blob 版只用于 look-dev 出图。
- 石圈、圆台这类圆件不要逐块建:整圈一个环,段数按需要取,块感靠每段顶点色抖动;段数太低会出刻面,不交刻面。

### 高模烘低模 + 总装导出

- 烘焙:`scripts/blender/bake_hi_to_lo.py`(`bake_color(hi_objs, lo, size, png, extrusion, ray)` + `preview_material`)。低模 = 能包住高模细节的外壳(石圈一个光滑环、叶团一个低段数穹顶、皮球单独低球),高模顶点色以 EMIT 烘进低模贴图(纯固有色,LabLit 自己打光)。穹顶太光会像香肠 / 馒头,要按花的位置起伏。
- 总装导出:从各件 .blend append → 每件合成一个 mesh、原点底部中心 → 三角预算门(超了先降段数 / 倒角 1 段,最后才 Decimate)→ 每件一个 FBX(`bake_space_transform`、`add_leaf_bones=False`、贴图 COPY)+ `<POI>_placement.json`(件名 / 位置 / 朝向,复用件写 `KIT:` + 工程 prefab 名)→ 出评审图 + FBX 回读尺寸。现成样板是 Extraction `ArtWork/J01v7_PARK_20261109/gen/park_final.py`。
- 坑:单件渲染脚本把其它物件 `hide_render=True` 存进了 .blend,append 后整场评审图里的件全没了;append 后一律 `hide_render=False`。改了单件脚本要重跑它再总装(否则回读查出的还是旧尺寸)。
- 复用库里的件先渲一眼、和拆件格对上再用,对不上就新做。

## 照参考建小件:先逐块写清,再同角度同区域核

勾哥打回过的根因:"对参考的刻画不够仔细,总是丢掉或是增加一些细节"——看个大概就按常识搭、只看整体缩略图验收、被打回只补点到的那一处。所以**先加载 reference-replicate**(skill 闸会拦),下面几步是它在小件上的补充:
1. 动手前把参考裁出局部、放大,逐块写一行:是什么、从哪到哪(地面/箱沿/半高)、凸出还是凹进、挨着谁、参考里**没有**什么。只建这张表里的东西。
2. 每轮用 `scripts/kit/closeup.py` 按参考的角度出同一区域的放大图,和参考裁图左右并排,逐行对表。
3. 被打回时回到第 1 步重核整块,不只补点到的那处。
4. 参考的比例和设计数据冲突时默认以设计数据为准,不用问。
5. 先用 `refkit.py measure` 量关键比例再搭(腿长和头宽这类比例一量就知道差多少);先定姿态和开合状态(倒地/立着、开/关)。
6. 勾哥的打回很短时,先在图上圈出理解的位置问"是这里吗"再改。
7. 白模形状没过,不进 paint-over。
