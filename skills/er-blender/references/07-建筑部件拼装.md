# 07 建筑与联邦小件:先做部件,再按设计坐标拼

2026-10-30 勾哥定:POI 建筑优先在 Blender 里做,先拆成墙、门框、屋顶、壳段等部件,再组合起来;建筑直接落在地面上,**不做地板**(也不做印章基座);部件库 Claude 直接做,不派 sol。首批 J01 做完后勾哥评价"建筑和小物件建模非常棒"。产物和完整记录在项目 `ArtWork/J01_POI_Kit_20261030/README.md`。

脚本在 `scripts/kit/`(全部 `blender -b --factory-startup -P <脚本> -- 参数`)。它们是 J01 的生成器,换场景照着改参数或抄结构,不要从零再写。

| 脚本 | 做什么 |
|---|---|
| `kitlib.py` | 调色板(壳白 #C6CFDD / 面板灰 #606F84 / 深色 #465C6D / 发光 #8DFCF5 ≤5%)、`Part` 拼装器(盒、挤出截面、环、柱、拱顶截面)、倒角(Bevel 2 段 + harden normals)、顶点色 `Col`、布尔切口 |
| `build_sc.py` | 有顶屋:按 `pilot.json` 的墙段、门洞、房间、家具坐标拼整栋;分 Low / Up / Roof / Doors / Furniture 五组 |
| `hull.py` + `build_hulls.py` | 破损横卧舱生成器(穿行通道、两端破口、无顶、高壳留远侧、侧翻变体) |
| `build_ruins.py` | 遗址残件直接按设计多边形原位生成:横卧舱残壳条、立筒半壳、平台残脚板 |
| `props.py` / `furniture.py` / `build_props.py` | 16 种联邦小件和 6 种室内家具,尺寸从组件表读 |
| `review.py` / `board.py` | 两阶 toon 评审出图、对照板 |

## 做法
1. **先读三样**:设计数据(房间、墙线、门、组件尺寸和坐标)、过审概念卡、mo.co 参考(只用参考登记表本物件那一行的图,建筑外形不挂 mo.co,见 vault `mo.co截图/README_参考怎么选.md`;提取写进工作目录 `notes/`)。
2. **设计数据和参考图不一致时,以设计数据为准**(勾哥 10-31)。尺寸、高度、比例、房间、门、组件坐标都按数据;参考图只管数据没写的造型和画法。设计数据自己前后矛盾时(J01 有顶屋:pilot.json 写 6 m 墙加双坡顶,story_pass 写"拱顶长屋")才问勾哥。
3. **部件分组按游戏行为切**:有顶屋的墙和门框在 1.2 m 处拆成上下两件,屋顶单独一组。进屋时隐藏"屋顶 + 1.2 m 以上"这两组,就是试点要求的"屋顶淡出、墙裁到 1.2 m"。关闭的门板单独成件。
4. **落地不做地板**:墙和脚墩向地下多伸 0.3 m,防地形起伏露缝。
5. **大门放不进低檐时做"人口"门楼插件**:凸出墙面的门楼块,用布尔把拱顶在通道处切开(23 总纲 DNA2)。
6. **画风**(mo.co 提取):倒角约为短边的 4~6%;靠分块缝、腰线、压顶读结构;缝的底色要浅(J01 用 #8E9BB0),深色缝在游戏距离下会读成黑描边。
7. **出图**:每件出 46° 全景、3/4、游戏距离(屏宽 14 m)三张,橙色 1.52 m 胶囊当 Wren 标尺,和概念卡、mo.co 同尺度拼成对照板,亲眼看过再往下。

## 坑(J01 实际踩过)
| 坑 | 症状 | 做法 |
|---|---|---|
| 两个盒子顶面共面 | 顶上出现斜向刻面、闪烁(z-fighting) | 部件顶面错开高度;门楣和门柱不要同时覆盖同一块,门柱只到门高,门楣盖满 |
| 墙段在拐角、T 型交接处重叠 | 交接处闪烁 | 每个端点和交叉点放一根略粗的立柱盖住 |
| 色块抖动按"块序号"取值 | 同一块墙在 1.2 m 上下两半颜色不一样 | 抖动按块的平面中心算(z 不参与) |
| 绞盘、卷盘露出滚筒 | 读成绞盘机关(设计明令禁止) | 全封闭外壳,只露端盖 |
| 母舱南墙(镜头一侧)太高 | 挡住南侧设备带 | 镜头一侧的残墙压低;远侧屋顶残片不会挡 46° 镜头,可以放心做宽 |
| 残墙断口用尖锐锯齿 | 不像 mo.co 的块状断口 | 平台阶 + 短斜角,偶尔一个缺口 |

## 小 POI 一轮 15 分钟:拆解单 → 体块 → 叠图 → 细节 → 出图(11-09 勾哥定)

勾哥 11-09:「每个小型 POI 一轮建模在 15 分钟以内要返回截图」。返工的根因不是手慢,是没读懂参考就开建:比例、件数、被挡住的面、多出来的件,AI 看图最不准的就是这几样(VLM 数数、量尺寸、遮挡推理的公开基准都远低于人)。所以每轮把"看图"换成能核对的产物,每一步都有命令,不靠眼睛估。

| 分钟 | 做什么 | 命令 / 产物 |
|---|---|---|
| 0–3 | **拆解单**:设计数据(`small_poi_redesign_*.json` 的 pieces / geo、poi.py)抄成 parts JSON,每件写 `name / why(干什么用)/ cell(参考图格号)/ count / shape / at / size / z0`;`conflicts` 写设计数据和概念图对不上的地方(按设计数据做,列出来给勾哥看);`absent` 写参考里**没有**的东西。说不出 `why` 的件不建 | `refkit.py cells 概念图 --n 10 --out grid.png` 打格号;JSON 格式见 `scripts/kit/blockout.py` 文件头,样例 = LH 河口灯标(下文) |
| 3–5 | **体块**:只用盒子 / 竖圆柱,每件一个物件 `<id>_<名>` | `blender -b --factory-startup -P scripts/kit/blockout.py -- --parts parts.json --out x.blend`(约 3 秒) |
| 5–7 | **叠图自检**:俯视概念图上核位置和占地,46° 外观图上核比例;叠图偏了当场改 JSON 重跑体块,不等勾哥 | `py scripts/kit/overlay.py --ref topdown.png --blend x.blend --collection <POI>_Blockout --view top --out ov --pts "…" --check "…" --ref-mask "…"`;外观图同样跑 `--view g46`(每张约 3 秒) |
| 7–12 | **细节**:在体块上换成 `kitlib` 正式件(倒角、门窗、栏杆、压顶),只做拆解单里有的 | `scripts/kit/*`、`kitlib.Part` |
| 12–15 | **出图发勾哥**:评审图(46° 全景、3/4、游戏距离)+ 两张叠图板,一起 SendUserFile | `stage.py`;`ov/<label>_top_board.png`、`<label>_g46_board.png` |

**不进这 15 分钟的**:拆解单的盲审 subagent 放后台和建模同时跑(只给概念图 + parts JSON,让它找"参考里有、单里没有"和"单里有、参考里没有"的件),结果并进下一轮;Tripo 补背面只在看不清背面的大 POI 开工前跑一次。

### 叠图怎么用

- **对应点 `--pts`**:概念图像素 = 世界坐标(米,x 东 y 北,z 可省)。选地面上、设计数据定义了的点:台基 / 地块角、门槛两端、柱脚。2 点相似、3 点仿射、4 点以上单应。**同一张图只标一次**:对应点、`--check`、`--ref-mask` 存在概念图旁的 `<图>.overlay.json`,下一轮只要 `--ref --blend --collection --view --out`。角点先用 `refkit.py sheet` / `crop` 放大到 4–5 倍再读像素。
- **检查点 `--check "名:u,v=x,y,z@fu,fv"`**:u,v 是概念图里这个件的顶(塔顶、牌顶),x,y,z 是设计位置和高度,`@fu,fv` 是概念图里它的脚点。输出:体块投影离概念多远(px、约多少米);≥4 个同高对应点时还会反推概念图相机,给出"概念图把它画在多高 / 画在哪"。
- **读板**:左 = 概念图,中 = 叠体块,右 = 灰底 + 品红体块轮廓(每件单独描边)+ 青色概念主体轮廓;底部是残差、IoU / recall / precision、检查点。对应点残差 > 15 px 先重标点再看别的。
- **概念图透视不自洽**(AI 生成图常见):反推相机残差 > 15 px 时,高度一律标 `UNRELIABLE`,只当"差得多不多"的信号(LH r1:塔画到约 11 m,设计 8 m),不当精确数。这时位置和占地以 `top` 叠图为准,比例看 `g46` 叠图;`--view concept`(用反推的概念相机渲体块)只给透视自洽的图用(引擎实拍、Blender 渲染),AI 概念图上会把塔渲歪。
- **叠图对不上不等于体块错**:默认按设计数据(10-31),勾哥可以按次改(PARK r1 这次按概念图);小偏差不纠结、不同步回设计数据(11-09「概念图永远都是概念图」)。只列明显影响玩法的(搜点被挡、走不通、件伸出地块)。叠图的价值在体块比例和件有没有漏 / 多,不在逐米对齐。

### PARK 公园花园 r1 实跑(11-09,第一次完整一轮)补的口径

- **用时**:13:18 开工 → 13:20 体块 + 叠图(2.5 分钟,冲突全暴露)→ 13:23 细节首版 → 13:24 自查修 4 处 → 13:25 出图,约 7.5 分钟(不含我读图的时间)。细节脚本在 scratchpad `park/build_park_r1.py`,新 POI 照它抄结构。
- **看板的「俯视图」topdown.png 是 V5 46° 游戏镜头,不是正交**(11-05 定的出图口径):对它叠图用 `--view g46`;`--view top` 只给真正正交的俯视图。高的件(亭顶、灯头)在 46° 图上有视差,**位置检查点一律标脚点、z 写 0**,这样量出来的才是纯地面位置差。
- `--ref-mask` 圈的必须是被渲染集合里有的东西:地面没建时圈广场轮廓,IoU 没意义,只看检查点。
- 评审图用 Workbench `FLAT` + 阴影 + cavity,才是顶点色本色;`STUDIO` 会把粉紫压成深紫,别拿它判颜色。
- kitlib 新增 `vcyl`(竖圆柱 / 圆台 / 圆锥 / 正多边形柱,seg ≤ 12 时平边朝北)、`vring`(竖向圆环:花坛、树池、平躺车轮)、`beam`(两点间定向方条:绳、屋脊、斜腿);`blockout.py` 加 `shape: cone` 和 `seg`。
- 自查必过(本轮自己抓到的):细长件(绳、链)渲出来是不是成了片;屋顶坡度和参考比(八角亭 19° → 27°);件和件有没有穿插(树池压进喷泉);评审图颜色是不是被光压暗。

## 单件精度:每个件对着拆件图那一格做(11-09 勾哥定为这套工具的真正目的)

勾哥 11-09:「我做这个工具,skill 的目的是要求单个物品的建模精准,细节还原」,点名 PARK 石墩 + 木条长凳、高脚圆花坛没达标。

**流程(每件)**
1. **裁格**:`refkit.py crop parts.png --box <这一格> --zoom 3`,再裁场景图里它的位置;两张都 Read。
2. **单件拆解卡**(写进 parts JSON 该件的 `card`,或单独 md):子件逐条(石墩 ×2、木条 ×4 + 缝、前沿厚木边)、材质、接合(木条插进石墩)、比例、参考里没有什么(无靠背、无金属)。
3. **取色**:`refkit.py color` 每个子件取一次,用亮的那一簇。
4. **建**:每件一个函数(参考 scratchpad `park/park_items.py`:`bench / round_planter / box_planter`),植物用 `plants.py`。
5. **按那一格的角度单独渲**(正交,拆件图约 az −10 ~ −14、pitch 34 ~ 42),透明底,和裁格左右并排;按「形状 → 比例 → 子件数 → 接合 → 颜色」一次列全差异。
6. 两轮没收敛就停,换成量化对位(下一条),不继续凭眼睛调。

**11-09 PARK 实测:凭眼睛调比例是瓶颈。** 长凳 / 三种花坛 4 轮约 8 分钟;圆花坛到第 3 轮接近拆件图,长凳结构对了但比例 4 轮没收敛:两次读错拆件图(把透视下的端面看成斜面、把「高」看成「深」),叶子 3 轮才从「圆片 / 多肉」改成「尖叶莲座 + 花浮在上面」。
- 比例要量化:拆件图同一张里所有格是同一个相机(生图一次出的),标一次相机(拿直角最清楚的件,如长凳、花箱的四个角)后,每件的剪影 / 子件掩膜(按颜色分石、木、叶、花)和渲染对比 IoU,用搜索拟合尺寸参数,代替凭眼睛读。工具待建(`item_fit.py`,勾哥同意后做)。
- 植物先做单元库,单元过了再拼件(reference-replicate「先做单元库再拼整体」同理);`plants.py` 是 v0。
- 件之间互相独立,可以每件派一个子 agent 并行,主会话只看并排图验收(每个子 agent 带裁格、拆解卡、取色结果和 `park_items.py` 样板)。

### 面数预算(11-09 勾哥「要需要面数预算的限制」)

- PARK 11-09 实测:look-dev 版(光滑椭球叶片 / 花瓣、逐块石圈)圆花坛 32k、长花坛 32k、长凳 1024;低面数版长凳 276 和高面数几乎一样,花坛压到 300 时石圈出刻面、叶子成稀疏三角片——**花叶满的件 300 装不下,要么升档(M 1200),要么高模烘到低模贴图**,待勾哥定。

### 高模烘低模 + 总装导出(11-09 PARK,勾哥「高模烘到低模」「直到可以进入 unity」「15 分钟内」)

### 长凳为什么四版没做对(11-09 复盘)

1. 第一版标了「复用」就放占位盒,没看拆件图。
2. 没先定结构和锚点:长凳 = 两个支墩 + 横跨的坐面,坐高 0.42–0.47 m、坐深 0.4–0.5 m 是人体尺寸,应先钉死,其余比例从它推;我从像素直接推全部尺寸,每轮都在动坐高、石墩高、进深。
3. 单张 3/4 图读比例前没先定相机:宽、深、高三个方向的压缩率不同,我拿屏幕像素比当真实比例。
4. 透视歧义没用第二视角核:把透视下的端面读成「外侧斜面」、把「高」读成「深」;俯视场景图就在手边,没拿来核石墩平面形状。
5. 每轮同时改尺寸、倒角、相机,前后并排不可比,分不清是模型改对了还是相机变了。
6. 验收只靠「看起来更像」,没有剪影 / 分材质(石、木)掩膜的数字。

对应规矩:拆解卡第一行写支撑逻辑 + 功能锚点尺寸;每张拆件图先标一次相机并锁死,之后只动模型;平面尺寸用俯视图核;一轮只改一个量;验收看剪影和分材质掩膜的重合度(`item_fit.py` 待建)。

### 样例:LH 河口灯标 r1(11-09 工具试跑,不是交付件)

拆解单 19 类 24 件 + 4 条冲突(塔位概念偏西 2 m、门概念朝南 / 设计朝北、系缆桩设计坐标出台基、塔高 8 m 与平台 5.5 m 的理解)+ 5 条 absent。计时:拆解单 1.5 分钟(设计数据已有拆件表)、体块 3 秒、俯视叠图 3 秒(3 点仿射,残差 0,IoU 0.88,塔差 2.0 m、牌子差 2.3 m 一眼可见)、46° 叠图 3 秒(5 点单应,残差 8 px)。对应点:俯视 `228,411=-4.5,4.5;565,411=4.5,4.5;231,731=-4.5,-4.5`,外观 `140,575=-4.5,4.5,0.3;605,575=4.5,4.5,0.3;127,935=-4.5,-4.5,0.3;640,862=4.5,-2.47,0.3;560,935=2.9,-4.5,0.3`。

## 照参考建小件:先逐块写清,再同角度同区域核(10-31 工具箱打回 6 轮的教训)
勾哥:"对参考的刻画不够仔细,总是丢掉或是增加一些细节"。根因三条:看个大概就按常识搭(多了锁扣槽、上部包边,漏了整高竖条);只看整体缩略图验收;被打回只补点到的那一处。更上游的一条:这几轮一次都没加载 `reference-replicate`(它 10-16 就写好了同样的根因和 refkit 尺子),自己临时写脚本绕远路。所以**先加载 reference-replicate**(skill 闸会拦),下面四步是它在小件上的补充:
1. 动手前把参考裁出局部、放大,逐块写一行:是什么、从哪到哪(地面/箱沿/半高)、凸出还是凹进、挨着谁、参考里**没有**什么。只建这张表里的东西。
2. 每轮用 `scripts/kit` `closeup.py`按参考的角度出同一区域的放大图,和参考裁图左右并排,逐行对表。
3. 被打回时回到第 1 步重核整块,不只补点到的那处。
4. 参考的比例和设计数据冲突时以设计数据为准,不用问(10-31 工具匣保留 1.4×0.8)。
5. 先用 `refkit.py measure` 量关键比例再搭(三脚架第一版腿长只有头宽 2 倍,参考是 4~5 倍,一量就知道);先定姿态和开合状态(倒地/立着、开/关)。
6. 勾哥的打回很短时,先在图上圈出理解的位置问"是这里吗"再改("四角没有包边"被我理解反,白做一轮)。
7. 白模形状没过,不进 paint-over。
