# 02 bpy 5.1 可移植性与踩过的坑

这一页解决的是"同一段 bpy 换个版本、换台机器、从 MCP 挪到后台就报错"。原则只有一条:**先自省再写**,枚举、参数、节点 socket 都运行时读,不凭记忆写。下面的坑都在 ER 会话里真踩过,括号里是会话或记忆出处。

## 先自省

- 枚举运行时读:`[i.identifier for i in bpy.types.RenderSettings.bl_rna.properties['engine'].enum_items]`。5.1 的 EEVEE 标识是 `BLENDER_EEVEE`,`BLENDER_EEVEE_NEXT` 不存在——这个错在 09-04 到 10-25 之间重复了 4 个会话(d16253e2、bcfa7c7e、27a8c46a、61d5f841)。赋值放进 `try/except TypeError`,报错信息会列出合法值。烘焙 target、文件格式同理。
- operator 参数用 `bpy.ops.object.bake.get_rna_type().properties` 查,不猜。
- 节点按类型找,不按名字(名字会本地化):`next(n for n in mat.node_tree.nodes if n.type == 'BSDF_PRINCIPLED')`;Principled 的输入用 `inputs.get('Base Color')` 兜底(4.0 改过输入名)。
- 材质颜色写节点输入,`material.diffuse_color` 只影响视口。

## 上下文和 ops

MCP 执行环境和后台模式都没有 3D 视口上下文,`join / mode_set / uv.smart_project / object.bake / export_scene.fbx` 直接调会 poll 失败或报 `Context has no attribute selected_objects`。统一走 `_er_bl.ops_ctx(obj)`(内部是 `bpy.context.temp_override(...)`),别处不直接调 `bpy.ops`。能用数据 API 做的(bmesh 合并、`modifiers.new`、`new_from_object` 应用修改器、mesh 属性)优先不走 ops。`mode_set` 包 `try/finally` 回到 OBJECT。

## 操作"成功"不等于生效

operator 返回 `{'FINISHED'}` 不代表真做了,每步写完要读回验证。已知的静默失败:隐藏物体选不上,导出时被静默丢掉;`transform_apply` 对带动画的变换静默无效;多材质 mesh 导出成多个;FBX 导出要 `add_leaf_bones=False`、`bake_anim_simplify_factor=0`(动作烘焙那步 simplify 必须是 0)。

## 颜色和贴图

- 顶点色线性/sRGB 别转两次,转两次颜色发黑(er-pine-tree-gen)。
- bpy 里 light.color、world 色填线性值(#FFE6C4 这类先 sRGB→linear);评审图 view_transform 用 Standard,不用 AgX(对齐 Unity 用)。
- Tripo 的 UV 缝是断开的,减面前先按距离焊点,否则减面出脏面(feedback-desert-lab-lessons #17)。

## Windows 路径和脚本生成

heredoc 里写 Windows 反斜杠路径会出语法错(d127c153、7dc1a708 各踩过);bpy 脚本里路径一律正斜杠或 raw string。含反斜杠的脚本和 TSV 用 Write 工具生成,不用 bash heredoc / printf 拼。
