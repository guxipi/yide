## 6.2 配置:rig 段怎么填
坐标都在归一化空间:身高 1.0、脚底 z=0、x 居中、角色面朝 -Y、角色自己的左边在 +X。先渲一张有刻度的正面/侧面(`render_views.py` 正交图,1536 高 = 0.88 身高 + 上下各 92 像素,换算:z = (1444 - py)/1352)量出头发、裙子、背负件的位置。

- `chains`:每条链 `name`(`{S}` 会替换成 L/R)、`mirror`、`bones`、`parent`、`points`(bones+1 个点,沿着头发/布料中心线)、`region`(哪些顶点归这条链:x/y/z 范围,`absx`)、`require`(原始权重里 head 骨合计 ≥ min,防止把肩膀算进马尾)、`mode`(full = 整块跟链;partial = 父骨保留 `parent_weight`,用于刘海)、`spring`(Unity 弹簧参数)。
- `skirt`:扇区数、环心、半径、三层高度、外张系数、条带范围、**布料颜色规则**(亮度下限、饱和度上限、R≥B-0.03——低饱和规则同时抓住裙子内侧的阴影布料)、邻居投票次数、`hips_weight`。
- `rigid`:整块跟一根骨的硬件(背包罐体),`region` 内顶点 100% 给它。斜着的长件(Harrow 背后的长枪)再加 `capsule_radius`:只收离 head→tail 线段这么近的顶点,不然轴对齐的 region 会把背上的衣服一起收进去。
- `straighten_spine` / `straighten_legs`(默认 true):把脊柱骨拉成竖直、大腿骨拉直。建模图本来就要求脊柱直(见 01),所以默认开;如果勾哥决定某个角色的驼背就画在网格里,关掉 `straighten_spine`,并在报告里写明动画会把驼背拉直。
- `straps`:背带只给 Spine2/硬件骨/锁骨,而且**只收手臂不驱动的顶点**(`max_arm`)——10-07 背带规则把袖子后片也收进来,胳膊一摆就扯出白色尖片。
- `skirt` 可选键(10-25 Vesper 侧裙片加的,不配=Wren 原行为):`thin_max`(沿 −法线射线量厚度 ≤ 此值才算裙布,代替颜色规则;薄片裙片/下摆与实心腿、靴、短裤分得干净)、`arm_keep_radius`(离手臂/手指骨段这么近的顶点不进裙子,0.022 只保手套壳和指尖;0.045 会把手旁的裙片也排除)、`colour_rule.r_minus_b_max`(挡暖色皮肤)、`colour_rule.also_sat_min`(高饱和镶边直接算布料)。调完看 `labels_board`(按 tag/主导骨染色的三视图)和抬手飞条诊断,不只看数字。
- 没有的部件就删掉那一段(Harrow 没有裙子和马尾:`chains` 可能只剩帽子/马甲下摆,`skirt` 删掉)。

## 6.3 跑
```
F:/Apps/blender.exe -b --python scripts/blender/rig_build.py -- --config <cfg> --texture out/<slug>-tripo/tex/basecolor_clean.png
F:/Apps/blender.exe -b --python scripts/blender/rig_audit.py -- out/<slug>-tripo/rig/<slug>_rig.blend out/<slug>-tripo/rig/audit.json
py -3 scripts/deform_sheet.py --dir out/<slug>-tripo/rig/deform --out out/<slug>-tripo/rig/deform_sheet.png --crops out/<slug>-tripo/rig/deform_crops.png
```
rig_build 做的事见脚本头注释。要点:
- **保留 Tripo 的身体权重**(Wren r2 对比过:肩、胯、靴子 Tripo 原权重比我们重刷的好),只改次级部件和明显错误。
- 远距权重修剪(离骨段 > 12% 身高、权重 ≥ 0.1)**跳过 Head 骨**:Head 骨是头骨前面的一根细线,大头发和后脑天然离它远。10-07 的版本没跳过,1941 个后脑/头发顶点的 Head 权重被删、全掉到 Neck 上——转头时后脑不跟着转。已发货的 Wren 有这个问题(rig_audit 能查出来:far_body 1941)。修剪在重新归一化后重复做,全被剪光的顶点退回原来权重里离它最近的骨,不再一律给 Hips。
- 每条次级链末端加一根不变形的 `*_Tip` 骨,FBX 导出保留非变形骨(`export_deform_only: false`),这样 Unity SpringBone 挂在链的最后一节时也有子骨(10-07 的 Wren 最后一节没有子骨,SpringBone 用的是兜底方向)。
- 打印 `DEMOTED_UNWEIGHTED_DEFORM_BONES`:被降级的链骨 = 链比头发/布料长(Wren Hair_L_04/R_04 就是,马尾实际在 0.59 以上就结束了)。缩短 points 或接受。
- 打印 `MATERIAL_NAME`:Unity 材质 remap 的键,每次 Tripo 导出都会变(`tripo_mat_<uuid>`)。

## 6.4 门
1. `RIG_AUDIT PASS`(13 条):最多 4 骨、权重和 1、主导权重 < 0.5 的顶点 < 10%、远距身体权重 ≤ 0.1% 顶点(剩下的是脚跟/后领这种最近的骨本身就在 12% 边上的顶点;上千个就是真 bug)、跨侧 0、髋上大腿 0、零权重变形骨 0、镜像长度 < 2%、镜像位置 < 0.005、脊柱前后倾 < 3°、toe 0.6~0.8、锁骨离脖子、armature 缩放 1。
2. `rig_build.json` 里 `gate_body_p99_all_pass: true`:每个测试姿势身体边(不含次级链)的拉伸比 p99 ≤ 1.75(Wren 最差 arms_overhead 1.64)。极小的原始边(< 中位数 25%,多是 UV 缝和壳的接缝)不算,不然 max 永远上百、毫无意义(10-07 r2 报告里 max 142 就是这个)。
3. `DEFORM_GATES PASS`(10-26 加,补 rig_audit 头注自认的"肘/膝弯折不做数值检查"):`F:/Apps/blender.exe -b --factory-startup -P scripts/blender/deform_gates.py -- --in <最终 FBX> --out <dir> --label <slug>`,失败退出码 1。只判两项,都只在 arms_down_10(肩外展压到 10°)和 elbow_120_L 两个姿势判:**手臂钻进躯干 arm_in_torso ≤ 15%**(坑 77 的数值门;Tuba 实测左臂 30.36%/弯肘 21.42% FAIL,Wren、Rook2 为 0)、**小幅度姿势拉伸坏边 ≤ max(10, 0.2% 边数)**(Tuba 0.58%/0.24%,Wren 0.03%/0.05%,Rook2 0.02%/0.09%)。自相交、关节带体积、泄漏、压扁和大幅度姿势的拉伸只进 JSON 的 report 段,不判门——三个角色上这些数分不开好坏(照外部参考阈值原样用,Wren 会误报 14 条)。下垂测试角度固定 10°,别往下压(Wren 压到 5° 就到 14%)。阈值只用 1 个坏样本(Tuba)定,新角色出现边界值时以第 4 条看图为准并回来校阈值。
4. **Opus 打开 `deform_crops.png` 原尺寸看**(这一条才是决定性的,"报告里写着通过"不算证据):
   - arms_overhead:背包和背带没有黑色尖刺,肩膀不塌;
   - arms_forward_90 / elbows_bent_120:袖子没有碎片,肘在肘处弯;
   - deep_squat / running_stride:靴筒和大腿不分家,裙摆不裂开,没有黑白条纹;
   - torso_twist_35 / head_turn_40:腰和脖子接缝不撕,**后脑跟着头转**;
   - chains_outward_40:整束头发跟着摆,头皮不动;
   - skirt_lift_30:裙摆平滑上抬,不是锯齿。
5. 不过就只改 config 的 rig 段再跑(最多 5 轮)。要派给 sol:`templates/sol/rig_task.txt`,它只许改配置、不许改脚本,报告要写每个姿势看到了什么。

## 6.5 常见失败 → 修法
| 症状 | 原因 | 修法 |
|---|---|---|
| 举手时背包炸出黑刺 | 罐体/背带吃了上臂权重 | rigid region 盖全罐体;straps `max_arm` |
| 下蹲/跑步时裙子碎成黑白条纹 | 裙子顶点跟着大腿走 | 裙子身体部分只给 Hips(`hips_weight`),颜色规则 + 投票把内侧阴影布料也收进来 |
| 袖子后侧扯出白色尖片 | 袖子被判成背带 | straps 只收 `armw < max_arm` 的顶点 |
| 马尾几乎不动 | 马尾顶点没进链(region 漏了或 require 没过) | 看 COUNTS;放宽 region,检查 head 权重门 |
| 马尾链骨被降级 | 链太长 | 缩短 points |
| 转头时后脑不动 | Head 权重被远距修剪删了 | 已修(HEAD_KEEP);审计 far_body 上千就是它 |
| FBX 进 Unity 后挂在手上的枪 100 倍大 | 导出没用 FBX_SCALE_ALL,armature 根缩放 100 | 只用 `_bl.export_fbx` / `export_fbx.py` 导出 |

## 6.6 大动作崩衣服(10-08 Wren 根修,勾哥:"不修好,他们学了也是错的")
走、跑、跳、蹲时衣服崩,idle 看不出来。两个独立病根,分开修:
1. **权重台阶**(白缝、黑三角,不开物理也有):每条分区规则(裙摆、头发、背带、髋上清大腿)都是逐顶点硬赋值,规则边界两侧的相邻顶点权重突变;glTF 还在 UV 缝把顶点拆成两份(Wren 6313 组),两份权重不一样就能被扯开。`rig_build.py` 现在在所有规则之后做**接缝平滑**:找出相邻权重差 > 0.35 的顶点,外扩 5 圈,邻居平均 12 轮(刚性件不动),再让重合顶点共用一份权重;跨侧和髋上大腿两条规则改成 2~3 cm 内渐隐,不再硬删(硬删会重新切出台阶)。"主导权重 ≥ 0.5"那条规则已删,它本身就在造台阶。配置 `rig.weight_smooth`:enabled/jump/band_rings/iterations/alpha,默认值就是 Wren 的。
2. **弹簧没限制**(裙子整片翻起、头发炸成碎片,只在开物理时出现):见 08 的 `spring_limits.cs`。
**审计门**(`rig_audit.py`):`seam_jump_edges` = 相邻顶点权重 L1 差 > 0.6 的边(刚性件边界、手指之间的不计),≤ 0.3%;`seam_coloc_split` = 位置重合但权重不同的顶点,必须 0。Wren:旧版 3488 / 41,新版 164 / 0。
**看图门**:Unity 里不开物理用 SampleAnimation 拍 run、jump_down、wave_goodbye_01 的胶片条,和上一版并排,裁胯部和大腿根放大看,不许有白缝和黑三角。大腿从裙子里穿出来属于没有物理时的正常现象,不算失败,物理那一关在 08 验。

## 6.7 宽袖长外套(10-08 Vesper,所有开关都是可选配置,不配就是 Wren 行为,Wren/Rook 重跑输出逐字节一致)
Vesper 用默认接缝平滑过不了门(接缝 498、远距 289、5 个姿势 p99 2.0~2.8),根因有四个,各对一个开关:
1. **Tripo 把约 50% 上臂权重刷满整根宽袖直到袖口**:弯肘时袖子下半截被上臂拽开,也是远距权重超标的来源。`sleeve_flood.reweight`:袖子按"沿手臂的位置" s(0 肩、1 肘、2 腕、>2 过腕)重刷 Arm/ForeArm,肘部 `elbow_blend` 平滑过渡,靠肩 `top_blend` 内渐回 Tripo 原生权重。`sleeve_flood.exclude_hand`:连通灌水会顺着手腕灌进手,手保留原生权重。
2. **袖口要能垂**:`rig.sleeve_chain`(name/bones/start/full/end/parent_weight/spring),从前臂 s=start 挂到过腕 s=end 的短链,袖口顶点按 start→full 渐入链权重。链顶点**照样进拉伸门**(不豁免)。Unity 端 spring_spec 会自动加进 SPRING,spring_limits 给 `Sleeve|30|0.5`。
3. **分层衣服的平滑会串层**:Tripo 把外套和裤子、袖子和外套身体焊成一张网,双向扩散把外套的 Hips 权重带进大腿、把脊柱权重带进袖子。`weight_smooth.rank`({tag: rank}):顶点只吸收同 rank 或更低 rank 邻居的权重,过渡落在高 rank 一侧。`weight_smooth.extra_passes`:对指定 tag(可加 z 范围)单独再跑宽平滑——不进拉伸门的布料(下摆环、头发、袖摆链)和外套躯干/上半截袖子可以宽,身体关节附近不能宽(125° 举手时宽线性混合会拉坏更多边)。`skirt.top_ramp`:长外套在环顶之上还继续,环顶不能硬切,向下 top_ramp 内从自身躯干权重渐入。`sleeve_flood.torso_fade`:外套躯干在腋下附近渐回原生权重,保留的手臂权重只跟上臂(外套侧片贴着前臂,Tripo 给它前臂权重,弯肘会刺出来)。
4. **两片布挨着但不共用顶点**(袖子前缘贴外套前襟):两边权重不同,手臂一收缝就张开,ToonLit 描边壳的背面透出来成黑楔(Unity 待机装备页正面可见,10-07 旧版就有)。`weight_smooth.near_weld`(radius/tags/pairs/same_tag):距离 < radius 且网格不相连的顶点也当邻居参与平滑。same_tag 只能给布料区(sleeve、coat_strip),**绝不能给 body**——会把手指、两条大腿内侧糊在一起。
Vesper 定稿:审计 14/14(接缝 242/280、远距 22/36、重合点 0);拉伸 8/9,arms_overhead 1.96 不过——腋下以下一圈外套内表面,宽松上衣举手 125° 的几何上限(Rook 1.88 同类),看图自然。
**怎么测**:`tools/rig/pit_outline_test.py`(character-art-lab)在 Blender 里加反向外壳描边 + 手臂收拢姿势复刻黑楔,数腋下黑像素(Vesper 10203→2051);Blender 的测试姿势和 Unity Breathing Idle 不完全一样,最后必须进 Unity 用 ToonLit 拍两侧腋下特写确认。`rig_build.py --dump-labels x.json` 输出每个顶点归哪条规则,配 `tools/rig/stretch_heat.py` 出拉伸热力图,定位比猜快得多。

## 6.8 绑骨改了静止姿势,动作就要从这副骨架重新出(10-24 Rook2 根因)
rig_build 的镜像/roll 归零/脊柱拉直、assemble 换头、normalize 归一化都会改骨架静止姿势。Tripo GLB 里的预设/文生动作还是原骨架的,两者在 Unity 各建一份 avatar 时 T-pose 差几度(Rook2:腿 6°、脚掌 22°、手臂一截),肌肉重定向把差值当成每个动作的恒定偏移:交叉腿、脚尖点地、手臂外撑、微后仰。Wren 只是因为原骨架本来对称、改动量小才没露馅。
做法:`scripts/blender/anim_bake_to_rig.py <rig_final.blend> <anims.glb> <out.fbx>`(逐帧逐骨世界空间烘到最终骨架,髋位置按身高比缩放;动作名映射表在脚本顶部按角色改)→ `anim_verify.py <anims.glb> <out.fbx>` 打印每个动作 boneDirErr,**worst <1° 才算过**(rig_build 拉直脊柱/移 toe/镜像后骨向会恒差几度,这时用 `tools/vesper-cur/anim_verify.py` 的增量模式 VERIFY_DELTA 比 D=pose·rest⁻¹;导出必须 `bake_anim_simplify_factor=0`,见坑 123/124)(FBX 导入从第 1 帧起,脚本已按 +1 帧比)→ Unity 导入见 07 §8.8。导出的动作 FBX 必须和模型一样有两个顶层节点(脚本里多放了一个 Empty),否则 Unity 把 Armature 折叠进文件根,CopyFromOther 的 avatar 层级对不上(坑 109);Unity 里 `eval/hier_probe.cs` 核对。
