## 9.2 跑
```
bash scripts/unity/ingame_check.sh <Name> out/<slug>-tripo/unity/ingame
```
按钮名是 2026-10-07 的 UI(`Button_02`/`TabButtonContainer`、`PlayButton`、`Button_Deploy`)。日志里哪一步是 `none`,就在那一屏跑 `bash scripts/unity/ucli.sh buttons` 列出当前可点的按钮(名字、父节点、文字),换成新名字再跑;不要猜坐标点。

流程:Play(从 Boot)→ 等 25 秒到主页 → 底栏第二个页签 `Button_02`(父节点 `TabButtonContainer`)= 装备页 → 截图 → `PlayButton`(START)→ 简报室 → `Button_Deploy` → 等场景里出现 Expedition → 找 avatar 名含 Name 的 Animator → 截全屏 + 1440x2560 高清 → 抓 Console 错误(排除 Vivox/Chat 的已知噪音)→ **无论成败都 stop**(trap)。

状态截图已经在脚本里:出击后对每个状态(默认 `Sprint`、`death`、WeaponHold 层的 `HeroPistolRecoil`)把 Animator 定格在指定时刻截一张 `state_<名字>.png`,最后恢复。要换状态传第三个参数,例 `"Sprint:0:0.35,death:0:0.55"`;单独调试用 `ucli.sh eval scripts/unity/eval/anim_state.cs NAME=<Name> STATE=__layers LAYER=0 T=0` 列层。
这只是把动画状态定格来截图,证明不了"摇杆→移动"真的通;真操作要人或输入模拟,记为未验。

- **远征场景原点多一个运行时生成的 Wren 实例**,没存进场景文件,来源没查。
- Tripo 预设动作(Wren 26 条)已重定向并下载,没逐帧 QA,也没接进控制器;游戏里用的还是工程原有通用动作。
- 受击 flinch:HeroDamage 是 KayKit Generic clip,迁不到 Humanoid,受击动作失效。
- 鼓腮等表情只是画出来的,脸的轮廓不变。
